# 视觉策展增量存储

[English](guide.md) | 中文

## 变更

视觉策展保留原有 `visual_curator_<profile-hash>` 域作为只读基线，通过存储服务将新记录写入 `visual_curator_<profile-hash>_delta_v1`，复用现有的按记录布局。已有记录与提交清单的格式不变，不移动或删除原数据。增量单元保存基线的校验和；基线发生变化时，启动会拒绝混用这两部分。

备份必须包含两个单元。旧版插件只能看到基线，无法读取增量写入。此变更不影响 Session 日志或两个 SDK。

## 迁移

1. 停止运行中的 profile，备份视觉策展存储。使用 JSON 后端时，一起保留原有 `visual_curator_<profile-hash>.json` 文件及同前缀的 `visual_curator_<profile-hash>_delta_v1` 目录。
2. 更新插件并重启受支持的 `dsh` profile。增量单元会自动初始化，无须批量复制。若为存储域配置了显式后端路由，也为新增单元配置可用的 KV 后端。
3. 确认已有素材集、引用和分析结果仍可查看。创建一个素材集，重启 profile 后确认它仍存在。新写入不会修改基线文件。
4. 后续从同一个已停止的 profile 中同时备份两个单元。不要删除基线、丢弃增量目录，或使用旧版插件继续写入基线。若启动提示基线变更，恢复同一份备份中的两部分，不要手工合并文件。
