# AutoFlow 官方代码集成记录

[English](autoflow-upstream-integration.md) | 中文

本文记录 AutoFlow 的官方集成决定。当前目标为 `dsh-v0.2.0-rc.2`；下方早期版本章节保留历史背景。[文件清单](autoflow-local-change-manifest.json)保存当前比较基点及历史路径清单；[维护对照地图](cookbook/maintaining-autoflow-fork.zh.md)定位需要保护的定制实现。

## `dsh-v0.2.0-rc.2` 对比与集成（2026-10-08）

本次从官方发布标签拉取代码，旧官方基线为 `dsh-v0.2.0-rc.1`，两个标签间有 187 个提交。按禁止重命名折叠的路径统计，官方修改 1025 个文件；升级前 AutoFlow 相对旧官方修改 773 个文件，交叉路径 130 个。它们包括版本号、生成文件和文档，不等于独立功能数量。官方 `master` 已比目标标签更新，此次没有纳入标签之后的提交。

开始时 `main` 和 `deepseek-harness` 指向同一个自定义提交，因此镜像不能充当旧官方基线。已分别建立 `codex/backup-main-before-rc2-20261008` 和 `codex/backup-mirror-before-rc2-20261008`，再将本地镜像精确指向官方发布标签，并检查提交及文件树一致。集成在 `codex/integrate-dsh-rc2` 审阅；整理后将 main 与官方镜像推送自有远端；保留升级前备份标签，不创建新发布版本，不修改已有用户 profile，也不提交原有未跟踪的 `dsh-better-sidebar` 目录。

### 执行与数据流

`dsh` 选择 profile，`app-boot` 组合 bundle 和 overlay，Cordis 挂载服务；Web 请求经 `api-gateway` 和 controller 到会话、模型及交互服务，客户端通过 remotes 和 slots 渲染数据。功能合入需要同时检查服务、接口、客户端和日志，单独复制 TSX 不能完成升级。

模型目录由 `llm-pi-ai` 发现，共享选择与默认模型服务解析 route，设置持久化后用于新会话；已有会话从日志读取自己的 route。问题由交互服务登记、controller 发布、QuestionComposer 收集回复，服务分别结算等待与最终回答；会话日志和 SDK 保存可重放结果。终端由 terminal controller 订阅输出流，客户端面板卸载必须释放订阅。桌面命令由 Electron 启动管理器与 CLI shim 进入同一个 profile 启动链，信号和登录 shell 环境在各平台适配。

### 验证和已知限制

完整构建和构建后客户端类型检查通过。pi-ai 适配器、目录和流式参数聚焦检查 89 项通过；本地会话标题 22 项通过。交互、终端、右侧栏、计划和桌面流程聚焦运行共 1077 项通过，随后修复目录重命名相关断言并单独复验。

最终 UI 单元测试通过 395 项断言；官方 Web bundle 的自引用运行行使两个设置测试在导入时失败，已补齐测试脚手架的自包清单解析，并新增链接包回归，相关 34 项测试通过。浏览器的设置导航、模型双栏、选择菜单、问题和计划共 24 项断言通过；问题与计划的会话收尾比较仍受下述 Windows 技能目录差异影响，不把整个测试运行标为通过。独立临时 profile 的亮暗截图确认全窗口设置和模型双栏布局，未改动用户 profile。

文档同步 43 项门禁中 42 项通过，唯一失败来自原有未跟踪 `dsh-better-sidebar/README.md` 缺少双语配对；此次提交的文档配对已独立检查通过。全库 lint 排除该原有未跟踪目录后通过；未删除或改写其文件来消除门禁失败。提交文件 UTF-8、尾换行和 Git 差异检查通过。技能 frontmatter、调用元数据及只读脚本的污染镜像/错误祖先拒绝路径通过；新 Codex 会话的自动发现仍待验证。

升级前的独立 main 工作树复现了五项主题静态断言失败和四项插件浏览器单元测试失败：前者仍要求官方材质/圆角，后者仍要求旧依赖与插槽清单。本次不通过覆盖自定义视觉或跳过测试消除这些失败；它们仍是后续测试维护项。

三个新增官方会话快照在 Windows 上失败，差异为 Windows ACL 技能目录和进程退出说明；快照所属平台为 macOS/Linux，未用 Windows 输出覆盖跨平台录制。Windows Electron 信号测试在编译准备阶段失败，所需 Visual C++ 工具链未找到。真实模型 API、签名安装包和 macOS 运行结果未在此次本机验证。

下一次同步使用仓库技能 [autoflow-upstream-sync](../.agents/skills/autoflow-upstream-sync/SKILL.md)，指定旧官方标签、新目标和当前 main；其只读脚本会拒绝带定制代码的官方镜像。历史标签保留，回退基点为 `milestone/pre-upstream-v0.2.0-rc.2`；本节两个临时备份分支整理后删除；回退前先检查之后的新修改。

1. **功能新增：**原则上保留 AutoFlow 能力，包括状态、持久化、文案、无障碍与测试。若官方修改了同一接口或流程，应将功能适配到新的官方实现，不能整文件覆盖任一方。
2. **纯视觉改动：**默认保留本次样式基线。先对照官方与 AutoFlow 的亮暗模式效果；若拟用官方样式覆盖本地颜色、间距、几何形状、动效或布局，列出具体组件、差异和影响，并在改动前征求用户明确确认。未获确认时不覆盖。
3. **功能附带的样式：**官方新功能所必需的新增样式随功能合入，并与本地主题适配。若适配会替换现有样式，先按上一条取得确认；仅补充新功能所需的样式无需覆盖旧视觉。
4. **混合文件：**按代码块审查。功能逻辑可适配官方变化；同一 TSX/CSS 文件中的本地视觉仍遵守先确认后覆盖的规则，不对整文件使用“全部保留本地”或“全部采用官方”策略。
5. **生成及辅助文件：**选定代码后重新生成或更新相关快照、翻译记录、锁文件和文档。旧快照不能代替真实产品行为。

每个区域在下次集成时记录旧/新官方提交、涉及路径、选定的功能行为、视觉决定、聚焦验证和未解决冲突。视觉决定应附亮暗模式截图或可复现的浏览器状态；交互决定应覆盖对应的状态变化及失败路径。
