# 直接裁剪服务器接口

[English](direct-crop-server-api.md) | 中文

本适配器使用提供的 Postman 文件中的 OperateImage 接口。直接裁剪页面的“服务器图片”入口手动读取待处理列表；本地和收藏夹批次不会上传。接口描述见 [OpenAPI](direct-crop-server-api.openapi.json)。

## 连接与认证

接口基础地址、图片来源范围和认证来源可在连接面板保存。基础地址支持额外路径前缀，统一去除末尾斜杠：`https://example.com/api` 与 `https://example.com/api/` 都连接 `/api/OperateImage/pull.html` 和 `/api/OperateImage/receive.html`；根地址仍连接根路径下的接口。初始默认值可通过 `serverQueue` Cordis 配置提供，面板保存后由当前 profile 的连接记录管理。`concurrency` 默认 2，同时受 `limits.maxConcurrentRequests` 限制；`maxUploadBytes` 默认 32 MiB。后续切换线上域名不会把旧环境的任务自动传到新地址。

手动填写 token 时，原值只通过现有凭据服务保存到独立引用，连接记录仅保存引用名称；重新打开时不回显，留空保留已配置凭据。也可通过 `auth.ref` 使用已有凭据引用，或从指定的本地 Postman 集合中读取 POST 上传请求表单里字面量的 `token` 文本字段。文件须持续存在于填写的本地绝对路径；适配器不执行 Postman 脚本，也不解析集合变量。优先匹配基础地址对应的 receive 路径，也兼容所提供的根路径 receive 请求作为 token 来源。整个读取过程不修改文件。不复制 token 到模型输入、配置、任务记录或导出文件，也不改写认证文件与账号凭据。HTTP 和私有地址只允许用于显式启用的固定测试接口域名；原图仍必须来自单独允许的公开 HTTPS 来源。

## 获取与处理

`GET /OperateImage/pull.html` 通过查询参数发送 token，不发送 GET 正文。真实响应为 `{success:true,total,page,pageSize,data:[...]}`。每张图片使用 `id`、`name`、`img_url`，并保留 `md5`、`size` 和 `update_time` 用于版本与字节核验；文章标题、语言和其他元数据不能成为模型指令。当前只读取接口返回的一页，没有猜测分页参数或持续领取任务。

待处理列表通过已认证的资源接口按需加载预览，只能读取已保存队列中、符合图片来源范围的链接。预览依据字节签名识别 JPEG、PNG 或 WebP，即使来源返回 application/octet-stream 也可显示。预览不落盘，不作为原图导入；加载时显示缩略图骨架屏，失败后保留占位。

点击“处理并上传”时，先保存导入任务并返回稳定的批次 ID；原图下载随后由 Host 生命周期管理，不依赖弹窗或浏览器请求。直接裁剪页在处理任务创建前即可读取已保存张数、当前下载字节和失败状态，导入进行中持续刷新；重新进入页面可恢复显示。Desktop 重启会把未完成导入标记为中断，不静默重新下载；点击“继续导入”复用已验证的原图。MD5 或字节数不一致时保留成功文件，并在处理前停止。

Desktop 按连接、服务器 ID 和原图版本去重，不能按文件名或相同像素合并不同服务器任务。原图导入有界并发执行，复用已保存文件，校验声明的 MD5、容量、解码和存储限额；不以缩略图替代。断开和失败保留已完成导入。当前接口未提供不可变版本号，本地版本固定 URL、校验值、大小和更新时间，下载后另存实际 SHA-256。

选中的原图进入现有主体观察、安全区规划、裁剪或必要扩图、按需增强及独立复审。保护范围、原图一致性和最终复审要求保持不变。队列分别显示原图、处理及上传状态，可重新打开所属裁剪批次。

服务器图片默认筛选待处理，依据最近一次 pull 实际返回的 ID，与为保留流程、回执而留存的历史记录分开判断。旧快照需重新获取列表后才能准确筛选。仅可选择当前可见、服务器仍待处理、尚未分配任务且没有已接收或待核对传输的图片。

失败、中断的导入记录支持单条和批量移出列表。此操作只写入隐藏标记，保留导入历史、已验证原图、来源绑定及上传回执；运行中的导入不能删除。重新创建导入时可复用匹配的已验证原图。导入进度显示在标题旁，批次表格持续显示。

## 上传与恢复

只有最新处理任务中独立复审通过、没有未决检查的干净 PNG 可以上传；文件还须匹配目标尺寸及原图绑定。标注图、模拟图和其他批次成品不能替代。`POST /OperateImage/receive.html` 使用实际 multipart 编码，字段为 `token`、`ids[0]`、`images[0]`，由编码器生成 Content-Type boundary，不使用 Postman 中错误的 application/json 头。

上传前重新读取待处理列表，要求服务器 ID 及原图版本仍一致；记录消失或版本变化会在 POST 前停止。刷新列表仍保留本地已接手的任务和回执，不因服务端移出待处理队列而隐藏。

服务端校验要求每批 1～20 张。每张图片独立复审通过并保存成品后即进入上传队列，同批其他图片可以继续处理。适配器逐图提交，避免部分成功无法对应；本地先提交不可变上传意图，再发起一次 POST，保存成品摘要和回执。重复恢复不再上传已接收的成品。明确拒绝或发送前配置失败可显式仅重试上传，复用同一合格文件，不再次规划、生图或超分。

实际成功回执为 `{success:true,data:{total:1,updated:1,failed:0,skipped:0,results:[{index:0,id:69674,status:"updated"}]}}`。确认接收要求各计数一致、仅一条结果且 ID 对应本次提交；ID 可为规范字符串或安全的正整数。HTTP 成功不直接等于文件已接收。有界完整 JSON 回执经脱敏后保存，“核对已保存回执”可据此在本地恢复成功状态，不再次 POST；旧版不完整回执仍保留待核对。网络中断、重启中的上传或不认识的响应均记为“上传结果待核对”。本接口没有已确认的回执查询、租约或服务端幂等键协议，不能把待处理列表中消失当作接收回执，也不自动重复提交。已保存证据不足时，回执检查保留该状态；新增查询能力前需在服务器人工核对。
