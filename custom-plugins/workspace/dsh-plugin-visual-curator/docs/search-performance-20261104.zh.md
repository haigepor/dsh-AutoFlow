# 搜索实测：2026-11-04

[English](search-performance-20261104.md) | 中文

## 摘要

本参考记录使用视觉策展 0.2.7 进行的 28 次 Unsplash 只读搜索，以及单独使用 12 个固定公共汽车候选的原生模型对比。它区分候选召回、唯一图片、元数据线索和像素复核通过。实测支持召回 50 或 100 张候选池，并给出一个 12 图样本的两层筛选结果，不能证明普遍召回率、稳定的模型速度或来源接口的永久限制。

## 搜索含义

Unsplash 说明搜索会考虑标签、标题、故事、地点及收藏集合。多关键词先排列匹配全部标签的图片，再包含只匹配部分标签的图片；关键词不是严格的 AND 过滤。因此，把主体放在查询开头只能召回候选，不能证明主体出现或占据画面重点。[官方搜索说明](https://help.unsplash.com/en/articles/2574035-multiple-tag-searching)

本次短查询比长句保留了更多汽车元数据线索。首轮在当前启用的主体和环境方向做少量探测，再根据已保存的像素复核反馈加深有效方向，并保持同一任务固定的页数和候选预算。只有启用规则包含建筑环境时才使用建筑词，不能将其作为车辆图片的默认标准。

候选池与要求的合格图片数量不同。来源 ID 需要跨查询、跨页去重。元数据匹配或预览图复核通过都不能证明原图文件已经验证；来源原图不可用时，不能用预览图替代并宣称它是原图。

## 接口与限制

本实验使用当前源码适配器访问 Unsplash Web 搜索接口。公开 JSON API 的文档描述另一个入口，不能据此确定 Web 接口可持续请求的限流额度。

| 接口 | 参数与证据 | 限制含义 |
|---|---|---|
| 当前 Web 适配器 | GET https://unsplash.com/napi/search/photos；query、page 和 per_page | 适配器接受调用方页大小 1–100，实际最多发送 30 |
| 本次 Web 响应 | 请求 per_page 为 30、50、100 时均返回 20 条 | 这是本次观察，不是永久每页 20 张或请求速率的保证 |
| 官方公开 JSON API | GET https://api.unsplash.com/search/photos；query、page、per_page、order_by 及可选过滤参数 | 文档说明每页最多 30 条；这些限制不描述 napi |
| 官方公开 JSON API 速率 | Demo 每小时 50 次；获批生产应用每小时 1,000 次 | 这些数值适用于 api.unsplash.com；本实验不能确定 Web 额度 |

公开 API 的参数和限制以[官方 API 文档](https://unsplash.com/documentation#search-photos)为准。当前 Web 适配器在全站搜索中不发送方向、颜色、语言或收藏夹过滤参数。28 次调用没有遇到 HTTP 429 或搜索失败。

六次调用合计 6,072 ms。另一次五页测量在 3,939 ms 内返回 100 条记录和 96 个唯一 ID。sports car mountain road 的三页在 2,568 ms 内返回 60 条记录和 55 个唯一 ID；classic car architecture 的三页在 2,927 ms 内返回 60 条记录和 56 个唯一 ID。前七个短查询的首屏共含 140 条记录和 118 个唯一 ID。

这些数量说明本次工作负载的候选召回可行性，不能确定有多少候选通过像素粗筛，也不能确定 50 或 100 张候选任务需要多少次视觉模型调用。

## 测量方法

28 次调用由一次冒烟请求、21 次对照请求和六次连续翻页请求组成。它们使用 UnsplashApi 和 CurlUnsplashTransport，不带账号凭据、不重试，单请求期限为 30 秒，响应上限为 4 MiB。两个直接 per_page 探测使用相同传输层。请求在 Windows、Node 24.14.0 下串行运行，不包含图片下载或 LLM 请求。

计时从适配器或传输请求前开始，到返回已解析结果结束，包含 DNS、curl 启动、HTTP 和 JSON 处理。21 个对照样本中位数为 850 ms，按最近秩计算的 P90 为 1,216 ms；该进程首个请求耗时 4,014 ms，独立冒烟请求耗时 4,264 ms。来源缓存和网络条件未受控制，因此这些只是描述性样本，不是耗时保证。

全部对照耗时按请求顺序为 4,014；939；502；1,016；881；817；1,216；1,124；1,401；466；475；816；828；970；850；945；806；799；912；850；831 ms。六次连续翻页耗时列在候选池表中。余下一个样本为冒烟请求的 4,264 ms。

实验只保存聚合数量和耗时，不记录私有提示词、账号标识符、凭据、图片 ID 或带鉴权的响应正文。公共模式结果不能证明已选账号的行为，不能说明官方解释以外的关键词语义，也不能确定 Web 接口可持续请求的限流额度。

## 模型耗时

另一项显式启用的实验让两条路径使用相同的 12 个公共候选、已选原生模型、合成的汽车主主体与道路或森林规则，并发均为三。基线对每个候选进行一次最终复核；新 worker 先执行两批六图缩略图筛选，再深审留下的四张。每个原生请求都经过 NativeVisionProvider、已注册 LLM 适配器、附件接纳和独立临时目录中的 RunEngine 记录。

| 指标 | 单图最终复核 | 六图粗筛与深审 |
|---|---:|---:|
| 模型请求 | 12 | 6：两次粗筛、四次深审 |
| 墙钟耗时 | 98,976 ms | 80,904 ms |
| 下载图片字节数 | 2,765,703 | 1,187,664 |
| 图片传输次数 | 12 | 16：12 张缩略图与四张完整预览图 |
| 非缓存输入 token | 13,364 | 11,943 |
| 缓存读取输入 token | 15,360 | 5,888 |
| 包含推理的输出 token | 26,490 | 17,126 |
| 图片准备排队累计耗时 | 10,579 ms | 1,846 ms |
| 原生图片准备累计耗时 | 9,673 ms | 2,027 ms |
| 模型累计耗时 | 191,695 ms | 122,744 ms |
| 最终通过 | 1 | 1 |

本轮模型请求减少 50%，墙钟耗时减少 18.3%，下载字节减少 57.1%。粗筛拒绝八张，没有触发回退。基线通过的唯一一张没有被粗筛拒绝，也通过了新流程的最终复核。只有一张基线正例，不能确定普遍的错杀率。

连接预检在对比之外增加一次已提交模型请求和 35,921 ms，成功轮次合计 19 次模型请求。实验使用已注册模型的默认值，没有提高输出限制；为满足最多 40 次调用、10 分钟的硬上限，关闭了模型适配器与任务的重试。凭据文件字节保持不变。夹具将完整请求元数据和已接纳附件保留在独立目录供回放，输出聚合结果。

墙钟耗时覆盖 worker 执行至结果提交，包括缩略图加载、粗筛转换、深审预览图加载和存储写入，不包含候选收集与测例准备。上表排队与准备数值描述原生附件阶段，此阶段之前的缩略图准备仍计入墙钟耗时。并发请求的累计时间可能超过墙钟耗时。pi-ai 将非缓存输入与缓存输入分开计数，把推理计入输出。测例顺序及上游缓存未受控制；本轮是该样本的证据，不是经校准的性能保证，也不是原图交付对比。
