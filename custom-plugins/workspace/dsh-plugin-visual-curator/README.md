# dsh-plugin-visual-curator

English | [中文](README.zh.md)

## Summary

Build a visual style from selected reference dimensions, publish immutable versions, and use one fixed standard for image search and actual-image crop review. Human corrections remain auditable and affect future standards only after explicit publication. DSH carries this independent bundle with its installation and enables its nine Agent tools in newly initialized Web and Desktop profiles. Existing profiles retain their choices. Local records remain available without search or vision configuration, while operations that need those services fail visibly until configured.

## Use this package

### Enable the profile layer

In Plugin Manager, enable **Visual Curator** to use the installation-owned copy in an existing profile; no profile-local package installation is required. Restart an already running Host after updating the application's installation dependencies. An installation that does not carry this bundle can install a reviewed package artifact into the intended profile instead. Its [patch](cordis.patch.yml) mounts the business provider, six Skills, three Agent tool groups and three page entries, each with an independent switch. Skills register through the native catalog without writing Home files. The Host must provide profile context, storage domains, credentials, jobs, Plugin Manager, configuration editing, the skill catalog and Session storage. The Web client uses the standard Plugin Manager detail page. The package provides no application executable; launch applications through a supported `dsh` profile.

This bundle does not add itself to other profiles or change AFP. Turning it off removes its registrations, stops new work, cancels and drains active work, and retains saved data. A second Host writer for the same profile is refused; stop the first Host before reopening the writer.

### Configure external services

The Installed plugins detail page offers independent GitHub checks, updates and explicit automatic-installation opt-in through the same updater as AFP. Restart loads the matching Host, Client and patch; saved data, credentials and feature selections remain. The [release guide](release/README.md) owns the version family, exact-source assets and validation limits.

The vision settings page selects image-capable models from Settings → Models using the live native registry. Provider URLs, credentials and reasoning defaults remain centrally managed. Model and credential updates invalidate the shared catalog; failed providers retain a retry state without hiding healthy choices. Saving a different native selection verifies that its route still advertises image input. Existing HTTP deployments and frozen tasks remain readable; selecting and saving a managed model changes new tasks to native dispatch without migrating existing tasks.

Configure the provider row in the owning profile's Cordis overlay. `source` selects Unsplash or a generic HTTP JSON image source, including endpoint, method, query/cursor/page-size fields, response JSON Pointers and allowed media origins. New tasks default to `vision.backend: native`: select a registered `vision.provider` and image-capable `vision.model` from the project's model settings. Credentials, model capability checks, image normalization and streaming use the native LLM and attachment services. `limits` controls file/decode/storage limits, request and candidate budgets, retries, concurrency and deadlines. The [configuration parser](src/host/config.ts) owns accepted fields and defaults; configuration is resolved before the task snapshot is created.

Set `vision.backend: compatible` to explicitly select the backup HTTP interface using the saved endpoint and credential reference. Model failures never silently switch transports or issue an extra paid call. Frozen historical tasks without a backend retain their HTTP behavior. Existing observations remain readable after changing the backend; new native tasks use a new reviewer identity. See the [upgrade guide](../../../docs/upgrade-guide/v0.2.1-rc.3/visual-curator-native-llm/guide.md).

Native requests admit authorized remote image bytes through the attachment service without changing source references or export permissions. Download reservations, per-call timeouts, retry allowance and cancellation remain owned by the curator task. Remote images share one durable bundle reservation, settled to actual bytes after every transfer completes; unknown transfers retain the reservation. Actual admitted references and prepared call parameters are saved before dispatch; reported token usage, timing and finish state are retained on successful and failed responses. A complete response must include a native terminal chunk before commit; valid JSON alone does not confirm stream completion. Cache fields omitted by the native adapter are displayed as unavailable. The analysis sidebar counts uncached input, cache reads and cache writes as disjoint input amounts; it does not infer gateway-wide hit rates or create synthetic chat Sessions.

The analysis dialog’s context ring uses one analysis or summary request’s recorded model capacity and reported input plus output tokens, including disjoint cache amounts without counting reasoning twice. It retains the last measured request while newer usage is pending and labels that reading. Auxiliary compaction calls remain in cumulative usage but do not replace this reading. When no request has reported usage or capacity, those fields remain unavailable; current model settings never invent them. The same reading remains available in compact dialogs.

The most recently viewed analysis and its inspected inputs stay in Client memory for `limits.analysisCacheTtlMs` (default 60,000; zero disables reuse). Reopening a fresh completed task avoids another detail read; running tasks continue synchronizing. Manual refresh, mutations and authorization changes invalidate reuse. Newer task facts and failed refreshes retain the last valid view with required revalidation; failed or aborted reads never renew its lifetime. Loading placeholders use the Settings pages' low-contrast fill and sheen, with reduced motion support; the sidebar reserves more height for batch navigation and scrolls model facts separately when space is limited.

Unsplash media uses system DNS first, then bounded HTTPS DNS failover for connection failures. `source.unsplash.mediaDnsResolvers` configures the fallback services; its defaults are Google and Cloudflare JSON DNS endpoints, and an empty list disables fallback. Only the hostname is queried, without photo paths or account cookies. `mediaConnectTimeoutMs`, `mediaConnectAttempts`, `mediaDnsCacheTtlMs`, `mediaDnsFailureTtlMs` and `mediaDnsCacheEntries` bound connection racing, retries and caches; DNS lookups also share the request deadline. All resolved addresses must be public; the original URL hostname remains in HTTP and TLS verification. Authorization errors, certificate failures and responses already being read do not trigger DNS retry. `previewTransport: host` serves saved references, collection covers, gallery thumbnails and full previews through this same path by default; `redirect` explicitly restores browser-side CDN requests. Gallery projections add optional Host display paths while preserving original provider URLs for registration and export. The preview route accepts only the existing unsigned public Unsplash media policy, forwards no account cookies and creates no image records. Retried native calls reuse verified admitted attachments within the task instead of downloading the same image again.

Gallery metadata requests pass the complete checked address set to curl's native connection fallback within the existing connection timeout and read retry allowance. Cookies stay in private request files and TLS still verifies unsplash.com. Browser metadata cache version 2 discards older direct-image projections and reloads them; source collections, selections and stored references are unaffected.

`source.endpoint`, optional `source.lookupEndpoint` and `vision.endpoint` reject embedded credentials, query parameters and fragments. A vision base URL with no path or ending in `/v1` resolves to `/v1/chat/completions` or appends `/chat/completions`, respectively; other request paths stay unchanged. Set `source.allowedMediaOrigins` and `vision.localOrigin` to exact origins without paths or a trailing slash. The optional lookup endpoint refreshes media by its stable source ID; it does not restart an expired search from its first page.

Model settings shows the registered context capacity and output default as read-only values. New native tasks use `vision.useModelDefaults: true` and inherit output, reasoning and sampling controls through native `prepareCall`; `limits.maxVisionOutputTokens` remains for compatible HTTP and legacy frozen tasks. The context capacity is not an output cap. Request timeout, retry count and task deadline remain task-owned. A token-limited response stays uncommitted; unknown remote outcomes can still be billed.

Before native style induction, observation text passes through the profile Compaction service using the registered model capacity and native pressure policy. Human judgments, complete image identities and output Schema remain outside the summary. Compression calls consume the same task vision budget and deadline, retain input, output and returned usage, and reuse matching committed receipts. Failed compression stops final induction while preserving observations. No Session is synthesized. When Web isolates chat compaction inside Agent presets, the workbench mounts the same native Basic backend in its own disposable scope with automatic Session listeners disabled. An optional profile-level `compaction` field accepts native Basic policy overrides; it does not change chat instances. Legacy snapshots without the inheritance marker retain their original controls; changing the registry affects newly prepared native calls, whose resolved settings are recorded before dispatch.

`vision.vendorVersion` records the supplier's declared model version. Without that declaration, saved requests retain a replay limitation. Changes to model sampling, `limits.maxVisionOutputTokens`, `limits.maxReferenceImages` or `limits.maxReferenceBytes` produce a new reviewer identity. For formal search and crop tasks, create a new candidate and publish its release before using the changed review method. Existing releases retain their saved method.

Save secret values in DSH credentials. The plugin stores only credential references, initially `VISUAL_CURATOR_SOURCE_KEY` and `VISUAL_CURATOR_VISION_KEY`; changing a JSON field does not store a secret. Sources and media use bounded public HTTPS requests with redirect and DNS checks. An explicitly configured local vision origin is the supported exception for a local model. Arbitrary request scripts, model-supplied endpoints and remote collection writes are unavailable.

Budgets limit actual attempts, bytes and elapsed time. Retries spend the same task budget, and an interrupted external request retains its reserved quota because the provider may already have billed it. The implementation reports unknown cost; it does not enforce a currency-denominated spending cap or predict the final invoice.

### Review results and corrections

Search results keep original and final assessments separate. Required failures cannot be offset by preference scores, and unknown or technical failures do not become aesthetic rejection labels. Only distinct qualified final images count toward the target; a short result set retains its actual stopping reason. A preview without sufficient original pixels cannot satisfy a final-output pixel requirement.

Manual cropping has two confirmations: complete the adjustment to save and review a real derivative, then explicitly allow its use as a learning example. Closing a preview, downloading, accepting a batch or abandoning a drag creates no ideal-crop label. A legal manually selected image with visual warnings remains distinct from an automatically qualified result. No crop is enlarged, stretched or expanded to satisfy an impossible request.

Feedback defaults to task-only. Opt into the current style candidate before a correction can contribute to its next draft; task irrelevance, “not needed” and unknown remain separate from style rejection. Revisions append a new feedback record and move one effective head. Old releases and exports retain their original records. Agent suggestions never become authenticated human confirmations.

Review-queue fields identify uncertain judgments, technical failures, human/model disagreements and new source groups awaiting human review. `limits.reviewSampleRate` also selects ordinary passed or rejected images reproducibly from their image digests. Each task fixes its sampling rate at launch. Queue membership changes no feedback or release, and a new source group does not imply a newly detected semantic category.

Search feedback separates unavailable originals, download/import failures, technical review failures, uncertain decisions and visual rejections. Imported images appear during review; only saved selections count as final, and filters retain whole-run counts. Each conversation has one compact task card in the upper-right body gutter below the native checklist, outside tool-process disclosures. Both entries share an ordered vertical stack and hide when their gutter is narrower than 280px. Multiple tasks switch inside that card without combining their counts; results expand through the shared collapse component within a bounded height. Tool calls keep localized receipts and original call inspection. Session grants restore saved searches and crops independently of mounted tool views; only the selected Run reads previews. Closing the conversation stops observation. Terminal Runs stop polling; lightweight discovery detects new tasks or external resume while viewed. Reconnect retains confirmed counts and ignores obsolete responses. Output directories come only from committed delivery receipts; zero qualified results create no directory.

The task-details toolbar separates title and lifecycle actions, primary metrics with secondary disclosures, and result filters. Final selections include the target count; zero-valued technical counters remain under More statistics and nonzero failures stay visible. Delivery paths and diagnostics expand on demand. All results, final selections, needs review and the active category remain available; other empty categories do not add buttons. Image results use compact 200–224px tiles in normal-width panes, including single and sparse results. Each 16:10 preview contains the full image, with grouped state, dimensions and match information, two review-summary lines, and the existing details and crop actions. Complete notes remain in the native detail modal.

The upper-right task card separates its title and state, one brief, final-selection emphasis, compact counts and result previews. Status and image verdicts use the native Tag palettes; images retain their full proportions, and zero-valued technical diagnostics are omitted. Drag the left edge to change only this card’s width between 280 and 640 CSS px, within the conversation body. Its right edge and the native checklist’s width stay fixed. Double-click restores 300px; the focused separator supports arrow keys, Home and End, while cancelled drags restore the previous width. Width stays local to the current Session component and does not restart task observation. When expanded, the card fills the remaining conversation-body height below the checklist. Its header and actions stay visible while results scroll internally; expanding the checklist or resizing the body reallocates that height. Card height and results expand together using the theme motion tokens; collapsing restores compact height without remounting previews, and reduced-motion preferences disable transitions. Result scrolling pauses during height transitions and resumes with the shared scrollbar skin when settled. Wider cards use additional preview columns.

Find and crop defaults to all saved matches in the current collection, grouped by their original search or crop Run. Each batch keeps its timestamp, state, identity and match count; the reader can filter one batch, with separate batch and image pagination. An authenticated owner-only read gathers the collection’s results across conversations while retaining original Session resource grants; other collections and Agent tools cannot bypass their authorization. An unavailable Session keeps its batch with an explicit notice rather than appearing as zero results. Task details opens the original Run with its controls and diagnostics; returning to all batches leaves the single-Session scope. Collection changes cancel old reads and reject late responses. Reading starts no task and calls neither the source nor vision provider.

Batch results use the existing low-contrast card skeleton while the first page is loading; unknown counts remain placeholders. Reopening a collection or batch filter restores its loaded pages from a memory-only LRU cache and immediately refreshes in the background. Refresh failures retain visible cards. `limits.batchCacheTtlMs` defaults to 60000 and `limits.batchCacheMaxViews` to 8; zero disables reuse. Cache entries never outlive their Session resource grants. Manual refresh and batch deletion invalidate every cached filter in that collection; owner scope changes, connection reset and plugin disposal clear the entire cache. Aborted and failed reads do not extend cache freshness.

Batch results and detail reads build only the current page’s authorized image metadata and preview links; aggregate counts and ordering still cover the full task. Remote cards use the existing thumbnail route with lazy loading and asynchronous decoding; the larger preview opens on demand. Analysis detail, saved input and stream initialization share one synchronous verification snapshot; it never spans requests or the SSE lifetime. Owner view caches survive entering and leaving a Session detail, while authorization resets invalidate them. ### Scope and recover work

Client-created profile tasks and Agent-created Session tasks have distinct owners. Authorized owner actions must open the owning Session channel before reading its tasks, pixels or exports. Saving a Session result to the profile library creates an independent association and leaves the original Session ownership intact.

Navigating away leaves work running. Analysis cancellation acknowledges the stop request, aborts pending calls and retains committed results; its stopping state remains visible until drain completes. Explicitly cancelled analyses never recover automatically. System interruption of a new analysis preserves its run ID, original settings, deadline, spent quota and checkpoint; initialization creates a new attempt and continues unprocessed batches. Committed model responses replay from receipts rather than calling the provider again. Unknown requests retain reserved quota and can incur charges again on continuation. Legacy cancelled tasks remain cancelled. Search and crop tasks retain explicit pause/resume and provider-revision checks; their shutdown behavior is unchanged.

The context panel keeps the last request’s reported usage while the next analysis request is pending and labels it accordingly; counts and capacity always come from the same request. Analysis preflight opens an opaque native dialog with skeleton feedback immediately and can be cancelled before submission. Accepted starts return before background list polling. Pause analysis finishes and commits the current admitted request, then stops before the next dispatch. Continue analysis uses the same Run and committed checkpoints without repeating completed batches; cancellation still aborts in-flight work. Explicit pause survives restart, and neither pause nor continuation resets the original deadline or budget. A process loss before a committed receipt leaves its external billing outcome unknown.

The analysis dialog separates Model output, Activity log, Requests and Failure diagnostics. Request rows show saved outcomes, model identity and safe failure details; earlier failures remain visible after a later attempt succeeds and are labelled as historical. Missing details in older records remain unavailable. Continue analysis also admits explicitly retryable failed analyses when their original deadline and model-call allowance remain. It retries only unfinished work in the same Run, retains observations and all request receipts, and clears the current failure once continuation is accepted. An explicit failed continuation opens a bounded retry window for pending work; restart and automatic recovery do not replenish it. The original task deadline and total budgets never reset, and completed or cancelled tasks cannot resume in place.

The analysis header keeps its title and collection name on one line. Ended reference-import status moves to the profile sidebar above its analysis controls; active import progress remains beside the image grid. Ready profiles retain Analyze again. It opens the existing range confirmation with full reanalysis selected and does not submit until confirmed. Continue analysis resumes a recoverable Run, or opens an incremental analysis for the currently imported references when the previous Run has ended; that new task can reuse saved observations and does not restart a cancelled import.

Recoverable network and response-format failures retry only the pending request up to `limits.maxRetryAttempts`; zero disables retries. `limits.retryDelayMs` (default 1000) spaces retries linearly and the wait responds to pause, cancel and shutdown. Saved failure receipts preserve the retry allowance across restart, and the activity log exposes the retry phase. Missing observation uncertainty is retained as uncertain; invalid types, unknown image evidence and incomplete image coverage remain rejected with saved field diagnostics. Starting another analysis automatically reuses the largest matching partial checkpoint from a failed or time-limited task when references, feedback, draft rules and model parameters agree; cancelled tasks are excluded. The settings time budget covers all batches, so large collections need a sufficient `limits.deadlineMs` as well as request and call budgets. Analysis thumbnails use authorized small-image URLs while the native lightbox retains the original preview URL; failed previews show a bounded placeholder instead of broken-image text.

Reference prompt version `visual-curator-reference-v2` sends only the current batch's human judgments, projected to feedback identity, subject, judgment and context. Final style organization still receives all feedback, and the frozen task retains the complete original records. Output schemas precede dynamic inputs and request identities come last, preserving reusable prompt prefixes without changing image evidence. Incomplete or malformed stream frames retain diagnostics and use the same bounded retry policy; explicit authentication failures and invalid UTF-8 remain non-retryable.

### Split, compare and export

Confirm family membership before assigning learning, development or holdout groups. Original images, exact duplicates and their derivatives share a family. Unconfirmed similarity is not evidence of independent data; previously analyzed or calibrated families cannot become independent holdout data. Holdout images are excluded from induction and training exports; using revealed holdout errors to revise rules requires a new manifest with those families moved out of holdout.

Select related source groups and explicitly confirm their merge before reopening the split form. The merge saves immutable family aliases and membership confirmation while preserving the original asset records. Earlier splits whose groups now collide across sets cannot be used; create a new split with the combined group kept together.

Comparisons retain fixed release/candidate references, pixels, usage, feedback heads, raw counts and denominators. Recall includes every labeled positive, including review, technical-failure and unprocessed states; precision counts labeled qualified results. A zero denominator is unavailable. Budget exhaustion saves a partial report with every fixed input and an explicit outcome. Image-only comparison does not generate crops or establish crop-damage metrics; those metrics remain unavailable without the corresponding independent crop supervision. Comparison never changes a default release.

Exports support style packages, classification/preference/crop JSONL and Skill Markdown. A download is a versioned JSON envelope containing `files` with textual content/checksums and, only for an authorized with-bytes export, `resources` with media bytes encoded as Base64. File checksums are SHA-256 over exact UTF-8 content; business-record digests use separately versioned canonical JSON. References-only is the default. Image bytes require recorded permission and a successful integrity check; missing, corrupt or unauthorized bytes fail the export instead of producing a supposedly complete package.

Client `reference-analyze` accepts optional `buildDataset: true` for cross-image induction; omission retains legacy per-batch analysis. `export-start` accepts `analysisRunId` with `kind: "style"` and `purpose: "reference"`, requiring a completed analysis whose images, dimension intent and human judgments match the selected release. Existing record enums and schemaVersion remain unchanged. The versioned profile lives in the existing Run JSON checkpoint; original style exports and human-supervision formats remain readable. Machine observations never enter classification/preference/crop human-supervision rows.

Training exports include learning families only and retain the eligible human feedback IDs frozen at request time. Later corrections do not rewrite an existing snapshot. Preference ties and neither choices remain explicit. Generated Skills identify the release and required resources, require a missing-resource report when pixels are unavailable, and only produce downloadable artifacts. They do not modify Home instructions, activate in a Session, train a model or contain model weights.

Retrieval rotates one candidate per query, retaining stable source IDs for resume. Closing the dialog or stopping the conversation does not itself stop an accepted background Run. State updates follow saved revisions so an older running response cannot replace a confirmed terminal state. Stale private references fail before conversation creation; missing files, changed directories and unknown acknowledgements retain explicit recovery states.

The workbench launch summary sits beside the collection selector in the top header, without a separate content row. Its compact trigger shows task state and real counts; the native menu exposes the complete status, delivery directory and existing actions. Before a Run exists, the summary shows the requested target rather than a qualified count. Stopped tasks use a neutral status; incomplete results and failures retain distinct labels.

The launch dialog groups Dataset and Workspace above Search requirements, with a fixed footer and a scrolling form. Package dates appear once in the selector. One status notice replaces duplicate failure cards; error details retain the safe message, failed step and suggested action. Before launching with a selected dataset, the client reads the Host's support for dataset selection. If the running Host lacks this support, the client blocks submission and asks the user to restart the application service and refresh the page. It never removes the selected dataset to bypass validation. Previously unknown launch acknowledgements keep their operation identity if this read fails.

Final selections contain only saved selection records; preview searches label these Preview matches. The task header shows title, state, target progress and actions above the category filters. The native Task details menu holds the full brief, secondary counts, stopping outcome, delivery and diagnostics. Legacy warnings repeating a structured candidate ID and error code are omitted; other warnings remain. Needs review and All candidates retain uncertain images, source passes, rejected crops and technical failures separately. Preview cards open the public preview and do not offer crop actions. New model-profile tasks compile instructions from current enabled rules, and adjusted profiles do not reuse old search hints automatically. Final review uses the frozen rule-coverage-v2 recipe. Historical tasks and human releases retain their original recipes. Agent preparation discovers usages, source and limits; it cannot create human-owned usages.

The optional tools row exposes bounded style reads, search/crop starts, run reads, Agent suggestions and export starts/reads. Session tool results identify that run; the bundle checks Session ownership before dispatch and does not write experimental Session records.

Tool declarations add to the model's tool-schema context while enabled. The bundle does not inject a style into every request or change Home instructions. Individual vision calls consume their own text and image budget. Native receipts retain provider-reported token usage; unavailable cache fields remain unavailable. Exact billing and gateway-wide cache statistics remain supplier-owned.

## Known Limitations and Deferred Work

<a id="known-limitations-and-deferred-work"></a>

Only configured image sources and image-capable native LLM routes or the compatible HTTP backup are supported. There is no arbitrary-site crawler, paid-original acquisition, image generation, segmentation, embedding/vector retrieval, model training or remote favorite write. The system reviews currently recalled candidates and cannot claim complete-library recall. Original quality, licensing, export permission and aesthetic usefulness require the user's own verification.

Keyless fixtures validate control flow and exact image geometry. They do not validate a real source/model deployment, vendor billing, broad visual quality or suitability of a user's references. Supply actual endpoints, response mappings, credential references, model capabilities and authorized samples before treating those properties as verified. Image-only evaluation leaves unsupported crop metrics unavailable. Profile locking coordinates processes on one machine; shared storage across independent hosts is outside its supported locking model.

From this plugin directory, `node scripts/test-preview-search.mjs` exercises the production Run engine, Unsplash adapter, review provider, storage, launch admission and observation logic with controlled source/model responses. It checks query rotation, mismatch rejection, cancellation, zero original downloads and original-output regressions without external services. The native browser fixture and its preview checks live in `tests/fixtures/build-search-feedback.mjs` and `tests/fixtures/preview-search-browser.mjs`.
