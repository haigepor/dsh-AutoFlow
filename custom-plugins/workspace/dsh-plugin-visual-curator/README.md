# dsh-plugin-visual-curator

English | [中文](README.zh.md)

## Summary

Build a visual style from selected reference dimensions, publish immutable versions, and use one fixed standard for image search and actual-image crop review. Human corrections remain auditable and affect future standards only after explicit publication. DSH carries this independent bundle with its installation and enables its eight Agent tools in newly initialized Web and Desktop profiles. Existing profiles retain their choices. Local records remain available without search or vision configuration, while operations that need those services fail visibly until configured.

## Use this package

### Enable the profile layer

In Plugin Manager, enable **Visual Curator** to use the installation-owned copy in an existing profile; no profile-local package installation is required. Restart an already running Host after updating the application's installation dependencies. An installation that does not carry this bundle can install a reviewed package artifact into the intended profile instead. Its [patch](cordis.patch.yml) mounts the business provider, six Skills, three Agent tool groups and three page entries, each with an independent switch. Skills register through the native catalog without writing Home files. The Host must provide profile context, storage domains, credentials, jobs, Plugin Manager, configuration editing, the skill catalog and Session storage. The Web client uses the standard Plugin Manager detail page. The package provides no application executable; launch applications through a supported `dsh` profile.

This bundle does not add itself to other profiles or change AFP. Turning it off removes its registrations, stops new work, cancels and drains active work, and retains saved data. A second Host writer for the same profile is refused; stop the first Host before reopening the writer.

### Configure external services

Configure the provider row in the owning profile's Cordis overlay. `source` selects Unsplash or a generic HTTP JSON image source, including endpoint, method, query/cursor/page-size fields, response JSON Pointers and allowed media origins. `vision` names a compatible multi-image JSON model and endpoint. `limits` controls file/decode/storage limits, request and candidate budgets, retries, concurrency and deadlines. The [configuration parser](src/host/config.ts) owns accepted fields and defaults; configuration is resolved before the task snapshot is created.

`source.endpoint`, optional `source.lookupEndpoint` and `vision.endpoint` reject embedded credentials, query parameters and fragments. A vision base URL with no path or ending in `/v1` resolves to `/v1/chat/completions` or appends `/chat/completions`, respectively; other request paths stay unchanged. Set `source.allowedMediaOrigins` and `vision.localOrigin` to exact origins without paths or a trailing slash. The optional lookup endpoint refreshes media by its stable source ID; it does not restart an expired search from its first page.

Model settings exposes `limits.requestTimeoutMs` in seconds, `limits.maxRetryAttempts` and `limits.maxVisionOutputTokens` under the connection options. These apply to new task snapshots. Reasoning models may need a longer wait and a larger output budget for complete JSON. A response ending with `finish_reason: length` reports `vision-output-truncated`, including when no answer content remains after reasoning; it is never accepted as a complete observation. A timed-out request has an unknown remote outcome and may still be billed, so endpoint tests can use zero automatic retries.

New tasks default to `vision.reasoningEffort: high`. An explicit level is recorded in the request descriptor and reviewer identity; Provider default saves `null` and omits the request parameter. Legacy frozen tasks retain omitted parameters. Vision settings update through Cordis volatile references, while accepted tasks retain their original model, reasoning level and budgets. Saving shows an independent loading state and returns a lightweight configuration result; an unchanged save performs no profile write.

`vision.vendorVersion` records the supplier's declared model version. Without that declaration, saved requests retain a replay limitation. Changes to model sampling, `limits.maxVisionOutputTokens`, `limits.maxReferenceImages` or `limits.maxReferenceBytes` produce a new reviewer identity. For formal search and crop tasks, create a new candidate and publish its release before using the changed review method. Existing releases retain their saved method.

Save secret values in DSH credentials. The plugin stores only credential references, initially `VISUAL_CURATOR_SOURCE_KEY` and `VISUAL_CURATOR_VISION_KEY`; changing a JSON field does not store a secret. Sources and media use bounded public HTTPS requests with redirect and DNS checks. An explicitly configured local vision origin is the supported exception for a local model. Arbitrary request scripts, model-supplied endpoints and remote collection writes are unavailable.

Budgets limit actual attempts, bytes and elapsed time. Retries spend the same task budget, and an interrupted external request retains its reserved quota because the provider may already have billed it. The implementation reports unknown cost; it does not enforce a currency-denominated spending cap or predict the final invoice.

Model & gallery settings separates the vision form from a multi-account Unsplash browser. Add account opens `https://unsplash.com/login` in a separate local Chrome or Edge window. Complete any website check and sign in there; the Host reads only cookies affecting the Unsplash API URL, verifies the current user and stores the session through DSH credentials. Passwords stay on the website, and personal browser profiles are not read. The login window shares the gallery request User-Agent, and capture starts after navigation commits. Visitor cookies do not start account validation; website access checks remain visible while polling. Mask clicks retain the sign-in dialog; Cancel, its close control or Escape requests cancellation. Every attempt uses a temporary profile that closes after capture, cancellation or timeout. Reconnect checks the saved user ID. Adding an already connected identity updates its existing session and retains its account ID, credential reference, custom label, list position and default selection; it does not add another account card. A reconnect signed into a different identity fails with a distinct account-mismatch message. Configuration stores only account ID, label, user ID, username and credential reference. Set `source.provider` to `unsplash`; `source.unsplash.accounts` holds these account descriptors and `source.unsplash.defaultAccountId` selects one search account or `null` for public search. Connections and default selection save immediately. Advanced settings opens the original HTTP JSON provider in a modal with `source.provider: generic`.

Reference gallery collection opens an account-scoped modal with a fixed-height account pane and independently scrolling content; narrow windows use a bounded horizontal account strip. Choose a collection to read every photo page up to `limits.maxGalleryReferenceFiles` (default 10,000). Validated pages appear immediately while later pages load; exclusions survive incoming pages and retries. Registration stays disabled until every page succeeds. The dialog selects available non-premium photos by default and reveals `limits.pageSize` more previews near the bottom. Cancel reading retains previews and permits a complete retry. Adding retains the current image set and positive/negative role, in `maxImportFiles` batches with fresh revisions.

After confirmation, the Host owns the reference task. Closing its dialog, changing collections or reloading the page does not stop later batches. The collection menu and workspace share committed counts and phases; Stop retains confirmed results, and unknown receipts stop further writes. Only one reference task may write a collection at a time; analysis and archival wait until it ends. Host restart marks unfinished tasks interrupted without automatic replay. Ordinary referencing does not start a model. Image lists load the current collection on scroll, with separate saved role totals, loaded counts and task progress. Appends preserve existing pagination; failures keep visible images and offer retry. Progress reads do not rebuild complete workspace snapshots.

Gallery views register remote references without downloading, converting or storing image bytes. Records retain approved public preview URLs, account/source identities and provider-reported dimensions. Analysis sends these URLs as `image_url` to the vision API; the provider must be able to fetch them. `remote-url-v1` identifies a URL descriptor, not pixel bytes. Remote observations contain no fabricated byte measurements, and reference packages include the URLs and replay limitation. Cropping and byte exports require verified byte-backed images. Existing local paths and byte imports remain readable. The explicit `gallery-import` API keeps its previous byte mode unless `mode: remote-reference` is supplied by the gallery UI. The UI verifies Host support before submitting a remote registration; an outdated Host refuses the operation instead of silently downloading images.

Registration reports verifying, referencing and saving stages plus per-item progress. Cancel referencing interrupts pending lookups and stops later images and batches. Already-admitted atomic commits finish, and their successful prefix remains in the image set. Unknown receipts stop later batches and are not retried automatically. Cancel, progress and metadata are scoped to the owning account and Session; leaving the view stops its polling and requests cancellation.

Each account has separate Collections and Bookmarked photos views. Private reads verify the saved user ID against the session and reuse successful checks for `source.unsplash.identityCacheTtlMs` (default 180000; zero disables stored success). Reuse requires the same API instance, account ID and expected user ID; credential or transport changes replace the instance. Expiry, explicit refresh and authentication refusal invalidate reuse. Byte imports and explicit account validation still request fresh checks. Cancelling one reader does not cancel other readers of a shared pending check. Inside a collection, search matches image titles and photographers across every metadata page; clearing it restores the collection. The Search library tab searches all Unsplash photos. Its adapter accepts arrays and results envelopes; continuations retain page offsets and ID digests instead of discarding extra items. Changed partial pages require an explicit listing refresh.

Refresh this view invalidates that listing's pages before reading again. Expired pages and old connection revisions cannot satisfy reads; full caches evict older pages. The cache stores no image bytes, Cookie or authorization inputs. If session storage is unavailable, the memory cache keeps the same page and byte limits. Imports and login operations always reach the Host.

The settings overview can scroll out of view; the gallery uses the full scroll-viewport height and stays at its top inset while the result list scrolls independently. The compact toolbar aligns with the public-search row and omits duplicate account names; gallery tabs combine small icons, a subtle selected background and the shared sliding underline. Select all loaded includes the currently loaded matching non-premium photos; deselection retains selections outside that scope. Gallery imports use fresh-revision `maxImportFiles` batches and stop on unknown outcomes. The selection bar keeps the target image set and import actions together, using two rows in narrow windows. Collection references use the same cache, skeleton and preview components.

Choose photos and a target image set, then Add references or Add & analyze. Registration pins source and account identities, retains individual receipts and adds positive remote references without copying pixels. Local-path references leave originals in place. Gallery registration is references-only and does not authorize image-byte export. Unsplash+ photos retain their premium marker; previews cannot substitute for a deliverable original. Analysis and reference packages use the automatic model-profile workflow. Source ID `unsplash` uses the selected account for fixed-style search; without explicit queries, the saved profile's search hints become retrieval keywords. Screening, crop planning and final review receive the frozen matching prompt and alternative rule groups. The Unsplash Web adapter derives its read behavior from the supplied interface package and verified live responses. ### Review results and corrections

Search results keep original and final assessments separate. Required failures cannot be offset by preference scores, and unknown or technical failures do not become aesthetic rejection labels. Only distinct qualified final images count toward the target; a short result set retains its actual stopping reason. A preview without sufficient original pixels cannot satisfy a final-output pixel requirement.

Manual cropping has two confirmations: complete the adjustment to save and review a real derivative, then explicitly allow its use as a learning example. Closing a preview, downloading, accepting a batch or abandoning a drag creates no ideal-crop label. A legal manually selected image with visual warnings remains distinct from an automatically qualified result. No crop is enlarged, stretched or expanded to satisfy an impossible request.

Feedback defaults to task-only. Opt into the current style candidate before a correction can contribute to its next draft; task irrelevance, “not needed” and unknown remain separate from style rejection. Revisions append a new feedback record and move one effective head. Old releases and exports retain their original records. Agent suggestions never become authenticated human confirmations.

Review-queue fields identify uncertain judgments, technical failures, human/model disagreements and new source groups awaiting human review. `limits.reviewSampleRate` also selects ordinary passed or rejected images reproducibly from their image digests. Each task fixes its sampling rate at launch. Queue membership changes no feedback or release, and a new source group does not imply a newly detected semantic category.

### Scope and recover work

Client-created profile tasks and Agent-created Session tasks have distinct owners. Authorized owner actions must open the owning Session channel before reading its tasks, pixels or exports. Saving a Session result to the profile library creates an independent association and leaves the original Session ownership intact.

Navigating away leaves work running. Analysis cancellation acknowledges the stop request, aborts pending calls and retains committed results; its stopping state remains visible until drain completes. Explicitly cancelled analyses never recover automatically. System interruption of a new analysis preserves its run ID, original settings, deadline, spent quota and checkpoint; initialization creates a new attempt and continues unprocessed batches. Committed model responses replay from receipts rather than calling the provider again. Unknown requests retain reserved quota and can incur charges again on continuation. Legacy cancelled tasks remain cancelled. Search and crop tasks retain explicit pause/resume and provider-revision checks; their shutdown behavior is unchanged.

### Split, compare and export

Confirm family membership before assigning learning, development or holdout groups. Original images, exact duplicates and their derivatives share a family. Unconfirmed similarity is not evidence of independent data; previously analyzed or calibrated families cannot become independent holdout data. Holdout images are excluded from induction and training exports; using revealed holdout errors to revise rules requires a new manifest with those families moved out of holdout.

Select related source groups and explicitly confirm their merge before reopening the split form. The merge saves immutable family aliases and membership confirmation while preserving the original asset records. Earlier splits whose groups now collide across sets cannot be used; create a new split with the combined group kept together.

Comparisons retain fixed release/candidate references, pixels, usage, feedback heads, raw counts and denominators. Recall includes every labeled positive, including review, technical-failure and unprocessed states; precision counts labeled qualified results. A zero denominator is unavailable. Budget exhaustion saves a partial report with every fixed input and an explicit outcome. Image-only comparison does not generate crops or establish crop-damage metrics; those metrics remain unavailable without the corresponding independent crop supervision. Comparison never changes a default release.

Exports support style packages, classification/preference/crop JSONL and Skill Markdown. A download is a versioned JSON envelope containing `files` with textual content/checksums and, only for an authorized with-bytes export, `resources` with media bytes encoded as Base64. File checksums are SHA-256 over exact UTF-8 content; business-record digests use separately versioned canonical JSON. References-only is the default. Image bytes require recorded permission and a successful integrity check; missing, corrupt or unauthorized bytes fail the export instead of producing a supposedly complete package.

Client `reference-analyze` accepts optional `buildDataset: true` for cross-image induction; omission retains legacy per-batch analysis. `export-start` accepts `analysisRunId` with `kind: "style"` and `purpose: "reference"`, requiring a completed analysis whose images, dimension intent and human judgments match the selected release. Existing record enums and schemaVersion remain unchanged. The versioned profile lives in the existing Run JSON checkpoint; original style exports and human-supervision formats remain readable. Machine observations never enter classification/preference/crop human-supervision rows.

Training exports include learning families only and retain the eligible human feedback IDs frozen at request time. Later corrections do not rewrite an existing snapshot. Preference ties and neither choices remain explicit. Generated Skills identify the release and required resources, require a missing-resource report when pixels are unavailable, and only produce downloadable artifacts. They do not modify Home instructions, activate in a Session, train a model or contain model weights.

## Understand the implementation

<details>
<summary>Implementation internals — click to expand</summary>

One Host provider owns authorization, explicit input resolution and workflow dispatch. The storage-domain repository writes immutable dependencies before replacing one aggregate manifest; only manifest-referenced records are visible. Expected revisions serialize edits, operation IDs recover completed commits, and a profile filesystem lock prevents a second Host from opening a competing cache. Unreferenced files or records left by a failed commit remain private.

The [domain](src/domain/index.ts) owns style versions, effective feedback, splits, evaluations and export snapshots; [media processing](src/media/index.ts) owns verified bytes, geometry and bounded external adapters. The [runtime](src/host/runtime.ts) separates durable tasks and attempts from process-local jobs. The [client](src/client/index.ts) and [Agent tools](src/host/tools.ts) call the same provider; the bundle patch changes no agent loop or Session event format.

<a id="model-experience"></a>
## Model Experience

The optional tools row exposes bounded style reads, search/crop starts, run reads, Agent suggestions and export starts/reads. It exposes no human-confirmation, publication, default-switching or split-confirmation command. Long operations return task handles; a start acknowledgment is not a qualified-image result. Tool results contain safe identifiers and authorized resource references; auxiliary vision requests retain their actual image order, digests, prompts, model/version declaration and validated output.

Tool declarations add to the model's tool-schema context while enabled. The bundle does not inject a style into every request or change Home instructions. Individual vision calls consume their own text and image budget; cached-prefix behavior and exact vendor token charges depend on the configured provider and are not measured here.

## Known Limitations and Deferred Work

<a id="known-limitations-and-deferred-work"></a>

Only the configured HTTP JSON source and compatible multi-image vision protocol are supported. There is no arbitrary-site crawler, paid-original acquisition, image generation, segmentation, embedding/vector retrieval, model training or remote favorite write. The system reviews currently recalled candidates and cannot claim complete-library recall. Original quality, licensing, export permission and aesthetic usefulness require the user's own verification.

Keyless fixtures validate control flow and exact image geometry. They do not validate a real source/model deployment, vendor billing, broad visual quality or suitability of a user's references. Supply actual endpoints, response mappings, credential references, model capabilities and authorized samples before treating those properties as verified. Image-only evaluation leaves unsupported crop metrics unavailable. Profile locking coordinates processes on one machine; shared storage across independent hosts is outside its supported locking model.
