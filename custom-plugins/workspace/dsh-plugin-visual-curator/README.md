# dsh-plugin-visual-curator

English | [中文](README.zh.md)

## Summary

Build a visual style from selected reference dimensions, publish immutable versions, and use one fixed standard for image search and actual-image crop review. Human corrections remain auditable and affect future standards only after explicit publication. DSH carries this independent bundle with its installation and enables its nine Agent tools in newly initialized Web and Desktop profiles. Existing profiles retain their choices. Local records remain available without search or vision configuration, while operations that need those services fail visibly until configured.

## Use this package

### Enable the profile layer

In Plugin Manager, enable **Visual Curator** to use the installation-owned copy in an existing profile; no profile-local package installation is required. Restart an already running Host after updating the application's installation dependencies. An installation that does not carry this bundle can install a reviewed package artifact into the intended profile instead. Its [patch](cordis.patch.yml) mounts the business provider, six Skills, three Agent tool groups and three page entries, each with an independent switch. Skills register through the native catalog without writing Home files. The Host must provide profile context, storage domains, credentials, jobs, Plugin Manager, configuration editing, the skill catalog and Session storage. The Web client uses the standard Plugin Manager detail page. The package provides no application executable; launch applications through a supported `dsh` profile.

This bundle does not add itself to other profiles or change AFP. Turning it off removes its registrations, stops new work, cancels and drains active work, and retains saved data. A second Host writer for the same profile is refused; stop the first Host before reopening the writer.

Release artifacts include the native image/reference picker implementation and its Windows worker.cjs; an older folder-only picker dependency cannot prevent plugin loading. koffi and the native-command runner remain declared dependencies. The worker starts only for a native chooser and belongs to that request's cancellation lifecycle.

### Configure external services

Training collections and their completed reference datasets belong to the application profile. They can be selected from another conversation and used with a different configured model; older Session-scoped dataset records remain usable without changing their files or repeating analysis. Selecting a dataset freezes its own references, rules and matching prompt. Other profiles, private image permissions and Session task records keep their existing access checks.

The Installed plugins detail page offers independent GitHub checks, updates and explicit automatic-installation opt-in through the same updater as AFP. Restart loads the matching Host, Client and patch; saved data, credentials and feature selections remain. The [release guide](release/README.md) owns the version family, exact-source assets and validation limits.

The vision settings page selects image-capable models from Settings → Models using the live native registry. Provider URLs, credentials and reasoning defaults remain centrally managed. Model and credential updates invalidate the shared catalog; failed providers retain a retry state without hiding healthy choices. Saving a different native selection verifies that its route still advertises image input. Existing HTTP deployments and frozen tasks remain readable; selecting and saving a managed model changes new tasks to native dispatch without migrating existing tasks.

Saved observations, automatic style profiles and reference datasets are independent of the selected execution model. Changing the model preserves their analyzed status, original model/request records and exported bytes. Incremental analysis can reuse committed observations from another model when image inputs, rules, judgments and processing still match; full reanalysis requires explicit confirmation for the selected model. New profile search and crop tasks freeze the selected reviewer and reference limits in their execution recipe, while continuing or recovering an accepted task retains its original configuration and budgets. Human-published releases and controlled comparisons retain their reviewer qualification checks.

Configure the provider row in the owning profile's Cordis overlay. `source` selects Unsplash or a generic HTTP JSON image source, including endpoint, method, query/cursor/page-size fields, response JSON Pointers and allowed media origins. New tasks default to `vision.backend: native`: select a registered `vision.provider` and image-capable `vision.model` from the project's model settings. Credentials, model capability checks, image normalization and streaming use the native LLM and attachment services. `limits` controls file/decode/storage limits, request and candidate budgets, retries, concurrency and deadlines. The [configuration parser](src/host/config.ts) owns accepted fields and defaults; configuration is resolved before the task snapshot is created.

Native model tasks delegate timing to the selected LLM adapter, including reference analysis, image-search review, crop proposals, evaluation and context compaction. The plugin imposes no single-model-request or task wall-clock deadline on these paths, including continuation of saved tasks. Native connection and idle handling, explicit cancellation, Host disposal, and call/page/byte budgets remain effective. Image-source and image-download requests retain their network timeouts; explicitly selected compatible HTTP tasks retain their existing request and task time limits. Saved models, references and observations remain fixed when continuing a task.

Style-summary v3 sends short image labels with one recorded canonical dictionary and restores every validated evidence and group reference before persistence. Older v1/v2 summaries remain readable. Streaming JSON retains a stable code-block view when bounded text retention removes its beginning; the last received readable prefix remains available until the complete saved result replaces it. Partial or failed output never becomes a completed observation.

Set `vision.backend: compatible` to explicitly select the backup HTTP interface using the saved endpoint and credential reference. Model failures never silently switch transports or issue an extra paid call. Frozen historical tasks without a backend retain their HTTP behavior. Existing observations remain readable after changing the backend; new native tasks use a new reviewer identity. See the [upgrade guide](../../../docs/upgrade-guide/v0.2.1-rc.3/visual-curator-native-llm/guide.md).

Native requests admit authorized remote image bytes through the attachment service without changing source references or export permissions. Download reservations, download timeouts, retry allowance and cancellation remain owned by the curator task. Remote images share one durable bundle reservation, settled to actual bytes after every transfer completes; unknown transfers retain the reservation. Actual admitted references and prepared call parameters are saved before dispatch; reported token usage, timing and finish state are retained on successful and failed responses. A complete response must include a native terminal chunk before commit; valid JSON alone does not confirm stream completion. Cache fields omitted by the native adapter are displayed as unavailable. The analysis sidebar counts uncached input, cache reads and cache writes as disjoint input amounts; it does not infer gateway-wide hit rates or create synthetic chat Sessions.

The analysis dialog’s context ring uses one analysis or summary request’s recorded model capacity and reported input plus output tokens, including disjoint cache amounts without counting reasoning twice. It retains the last measured request while newer usage is pending and labels that reading. Auxiliary compaction calls remain in cumulative usage but do not replace this reading. When no request has reported usage or capacity, those fields remain unavailable; current model settings never invent them. The same reading remains available in compact dialogs.

The most recently viewed analysis and its inspected inputs stay in Client memory for `limits.analysisCacheTtlMs` (default 60,000; zero disables reuse). Reopening a fresh completed task avoids another detail read; running tasks continue synchronizing. Manual refresh, mutations and authorization changes invalidate reuse. Newer task facts and failed refreshes retain the last valid view with required revalidation; failed or aborted reads never renew its lifetime. Loading placeholders use the Settings pages' low-contrast fill and sheen, with reduced motion support; the sidebar reserves more height for batch navigation and scrolls model facts separately when space is limited.

Unsplash media uses system DNS first, then bounded HTTPS DNS failover for connection failures. `source.unsplash.mediaDnsResolvers` configures the fallback services; its defaults are Google and Cloudflare JSON DNS endpoints, and an empty list disables fallback. Only the hostname is queried, without photo paths or account cookies. `mediaConnectTimeoutMs`, `mediaConnectAttempts`, `mediaDnsCacheTtlMs`, `mediaDnsFailureTtlMs` and `mediaDnsCacheEntries` bound connection racing, retries and caches; DNS lookups also share the request deadline. ### Establish a fixed style

The analysis range selects all references, positive examples only or counterexamples only, independently of observation reuse or confirmed reanalysis. Positive batches describe desired transferable traits. Negative batches describe visible mismatch evidence and uncertainty; their role alone does not identify which feature caused rejection. Conflicting roles remain explicit. Other roles retain committed observations whose image inputs, rules, judgments and processing still match. Missing observations stay pending, and role-scoped progress counts only selected images.

Once the references are complete, the model consolidates the saved observations into rules, alternative groups and a candidate-matching prompt, then automatically saves the checksummed full reference package. Counterexample-only collections retain observations and their role-filtered export without automatically defining a target style. A failed package commit can continue from the saved summary without another model request. The newest complete package stays first in the dataset list; changed current evidence labels it as the previous complete dataset. Search can select any authorized completed full version while analysis runs or is paused, freezing that version's rules and references independently of the current draft.

The collection menu can rename the selected image set. Renaming retains its identity, references and published versions, checks the current revision, and waits for an active reference writer to finish.

Rule checkboxes update immediately. Saves are serialized against the acknowledged immutable profile identity, and edits made during a save are merged into the next request. A save acknowledgement updates only selection metadata; retained observations and loaded reference pages are reused. Generation, search and ordinary closing flush pending edits first. Unknown receipts retry with the original operation identity; temporary closing does not promise rollback, and reopening reconciles the current saved selection.

Dataset observation tabs load their next page automatically near the bottom. A failed page retains visible rows and pauses automatic reads until Retry; the final page stops loading.

Search batches authorize and project only each requested image window. Unchanged polls retain page identities; settled history uses the configured cache interval, active or failed views use the normal poll interval, and expired preview grants refresh their pages. Saved Session metadata can authorize historical read-only previews after a Host restart without resuming an Agent. Missing Sessions remain unavailable, and control or mutation still requires a live owning Session.

The local workflow is “reference images → analyze through the vision API → organize and automatically adopt rules → optionally adjust → generate a reference dataset.” Every reference is analyzed within configured image and byte limits; cross-image induction receives all observations and fixed judgments. Representative pixels alternate positive and negative examples. Induction version two returns alternative style groups and default rule selections. Model profiles retain evidence, selection reasons and model authorship; they never create human-confirmed labels or overwrite human draft rules. Subject-only, unsupported and conflicting hints stay disabled by default. User selection and wording changes create immutable profile versions, survive reanalysis, and are disabled if their evidence disappears. Failed reanalysis retains the previous usable profile.

New profile analyses first request and commit per-image observations without rule proposals. Only after every observation batch is saved does the existing summarization stage induce rules, style groups and search hints. The observation mode is frozen in the task and recorded with its model-visible output schema; historical tasks without that mode retain their original response format when resumed. Checkpoint results keep an empty `suggestedRules` list for the observation stage, while standalone analyses still support direct suggestions. A failed final summary retains completed observation checkpoints.

No human publication or dataset split is required for this references-only package. Training exports include learning families only and retain the eligible human feedback IDs frozen at request time. Later corrections do not rewrite an existing snapshot. Preference ties and neither choices remain explicit. Generated Skills identify the release and required resources, require a missing-resource report when pixels are unavailable, and only produce downloadable artifacts. They do not modify Home instructions, activate in a Session, train a model or contain model weights.

## Understand the implementation

<details>
<summary>Implementation internals — click to expand</summary>

One Host provider owns authorization, explicit input resolution and workflow dispatch. The storage-domain repository writes immutable dependencies before replacing one aggregate manifest; only manifest-referenced records are visible. Expected revisions serialize edits, operation IDs recover completed commits, and a profile filesystem lock prevents a second Host from opening a competing cache. Unreferenced files or records left by a failed commit remain private.

The [domain](src/domain/index.ts) owns style versions, effective feedback, splits, evaluations and export snapshots; [media processing](src/media/index.ts) owns verified bytes, geometry and bounded external adapters. The [runtime](src/host/runtime.ts) separates durable tasks and attempts from process-local jobs. The [client](src/client/index.ts) and [Agent tools](src/host/tools.ts) call the same provider; the bundle patch changes no agent loop or Session event format.

<a id="model-experience"></a>
## Model Experience

### Prepare and review tasks

Find with this profile defaults to Preview links and automatically reuses a complete dataset matching the current collection and exact model profile. If none exists, Start creates the native Workspace conversation first, then prepares a reusable complete package in the background and continues searching. Saved complete versions from this collection remain selectable across conversations and are validated before conversation creation. Selecting a historical dataset freezes its own references, rules and prompt independently of the current draft; observation-only packages cannot define a search standard. The form explains missing complete packages and includes the native Workspace, prefilled brief and quantity; Keep original images and sized output remain explicit choices. Start freezes the profile, enabled rules, alternative groups, source and budgets. Preparation makes no paid model request and changes no global conversation model selection.

New launches include all current negative references by default, together with their eligible completed negative-package sources from this collection across conversations. Images are deduplicated by their immutable image version; removed references and references now marked positive are excluded. Current saved observations and judgments are frozen at admission, so later exports or edits do not change retries. The attached JSON keeps the primary package files and checksums intact and adds a negativeReferences section, which the Agent reads on demand as supporting evidence rather than positive query targets or confirmed training labels. Existing accepted launches retain their original input and attachments. Automatic complete-package generation requires the accepted human launch authorization; retries reuse its Session, message and package identities.

Preview searches currently require Unsplash. The Agent plans short English subject-first queries from current enabled rules and alternatives, loading dataset evidence on demand. Initial queries leave part of the page allowance for productive directions. Retrieval chooses candidates using saved review and selection feedback; weak-subject outcomes and all-duplicate pages do not count as productive matches. Unexplored directions can outrank low-yield pages. Stable source identities and per-query cursors support resume; an original-search checkpoint stores inactive query continuations separately and keeps its active query in the existing fields. Missing continuations retain the legacy meaning that earlier queries are finished. Search pages and source lookups consume the same saved budget, including after pause or restart. Review uses validated regular preview URLs, includes source and final rules, and creates neither original files nor crops. Preview matching does not verify original pixels or perceptual uniqueness. Original and sized outputs retain their existing final-pixel checks and Workspace delivery receipts.

New model-profile search and crop tasks pin the visual-curator-rules-v3 review recipe. V3 returns one subjectFocus entry per requested subject rule, with evidence from the candidate itself. A focal-subject requirement cannot pass when its structured evidence says the vehicle is incidental or absent, even if other dimensions satisfy the weighted ratio; uncertain evidence stays in review. Mere presence or exclusion rules do not acquire an invented dominance requirement, and deliberate subject-detail close-ups remain valid without imposing an arbitrary minimum area or complete-body requirement. The same alternative group must satisfy both focal and style checks. Contradictory rule judgments are retained in the saved model response and corrected in the assessment; missing or foreign candidate evidence is invalid output. Rule strengths and the saved profile remain unchanged. Frozen v1/v2 tasks retain their previous prompt schema and reference sampling.

V3 reference sampling prefers evidence for required and shared visual rules, covers enabled alternative groups, avoids repeated image identities and digests, and reserves room for a relevant contrast example within the frozen image/byte limits. Evidence exclusive to disabled groups does not crowd out current rules. Effective human judgments determine the model-visible positive, negative or undecided role; the imported role remains separately recorded. Reference selection is deterministic, introduces no model calls, and still checks actual byte limits after reading.

New searches collect 50 unique candidates across pages in the same Run, then screen small batches of actual thumbnails. `searchScreening.candidatePoolSize` accepts 50 or 100; `batchSize` defaults to 6 (1–16), and `maxScreeningImageEdge` to 384 (128–1024). Native requests also obey the model image-count limit. Analysis parameters in model settings can save these values. Source, page, byte, vision-call and concurrency limits remain shared; source or budget exhaustion uses the candidates actually retrieved. The first pass excludes only obvious mismatches for every enabled alternative group; uncertain images receive full review, and only full review can qualify a selection. Bounded first-pass retries fall back to individual review without creating visual rejections. Originals download after screening. Pause or restart reuses committed batches and reviews; older tasks without this policy retain their previous workflow. Task cards separate screened, first-pass exclusions and full-review counts. See [search performance research](docs/search-performance-20261104.md) ([中文](docs/search-performance-20261104.zh.md)) for measurements and limits.

Before downloading, new searches in the same collection exclude current references, previous selections, originals explicitly rejected at source or final review, and source identities excluded in the first pass. Rewording the task or switching reviewers does not reset this known-image deduplication. Unsplash uses photo IDs across accounts; other sources retain account scope. Only verified pixels use byte digests; remote descriptor hashes do not establish pixel equivalence. Historical reads still require authorization. Technical failures and uncertain outcomes are not permanently excluded, and other collections remain independent.

Disable batch screening in analysis parameters, or set `searchScreening.enabled` to `false`, to restore individual full reviews for new tasks. Accepted tasks retain their fixed policy and checkpoints. Screening is not guaranteed to be faster when most candidates already match or only a few images are needed.

Rules supported only by valid negative evidence can be saved and enabled. Explicit required exclusions must hold within their shared or alternative-group scope and cannot be compensated by preferences; preferred rules remain preferences. A negative role does not forbid every visible feature. Existing datasets retain their frozen content. To recover rules omitted by an older version, select All roles → Reuse and organize, generate a new profile and complete dataset, then search with that version. Compatible observations are reused, and preparation shows the actual remaining work. Re-exporting the old profile does not restore missing rules; explicitly disabled rules stay disabled.

Closing the dialog or naturally completing a conversation turn leaves accepted background Runs active. Explicitly stopping the conversation cancels its visual Runs and in-progress admissions, and stops its pending native search launch. Other Sessions and independently started workbench tasks remain active. Cancelled background tasks retain their results and notices without waking an idle conversation. Stop task in the conversation card stops the owning launch and its associated visual Runs, or cancels the selected Run when no launch exists. State updates follow saved revisions so an older running response cannot replace a confirmed terminal state. Previously confirmed results remain available, and conversation acceptance stays separate from retrieval and match counts. Stale private references fail before conversation creation; missing files, changed directories and unknown acknowledgements retain explicit recovery states.

The workbench launch summary sits beside the collection selector in the top header, without a separate content row. Its compact trigger shows task state and real counts; the native menu exposes the complete status, delivery directory and existing actions. Before a Run exists, the summary shows the requested target rather than a qualified count. Stopped tasks use a neutral status; incomplete results and failures retain distinct labels.

The launch dialog groups Dataset and Workspace above Search requirements, with a fixed footer and a scrolling form. Package dates appear once in the selector. One status notice replaces duplicate failure cards; error details retain the safe message, failed step and suggested action. The client checks Host support for dataset selection, automatic package preparation and negative references before submission. An older Host blocks submission and asks the user to restart the application service and refresh the page, preserving the selected dataset and any unknown launch acknowledgement identity.

After the native conversation is confirmed created, Start closes the launch dialog and opens that conversation without waiting for attachment or model preparation. Its task card shows the saved requirements and image target, keeps explanations and refresh under Task details, and supports cancellation. Attachment preparation and conversation submission have distinct hints. An accepted launch shows Preparing search with an explicit notice that the conversation has started but image retrieval has not. An actual image-search Run replaces preparation in the same card with real progress and then completion or failure. Preparation does not invent image progress or occupy the composer. Retrying an unknown acknowledgement also recognizes the request already claimed by a running turn, so preparation does not enqueue it twice.

Final selections contain only saved selection records; preview searches label these Preview matches. The task header shows title, state, target progress and actions above the category filters. The native Task details menu holds the full brief, secondary counts, stopping outcome, delivery and diagnostics. Legacy warnings repeating a structured candidate ID and error code are omitted; other warnings remain. Needs review and All candidates retain uncertain images, source passes, rejected crops and technical failures separately. Preview cards open the public preview and do not offer crop actions. Open task in the conversation card obtains the original Session grant; grants stay in memory and Return to library clears that scope.

New model-profile tasks compile instructions from current enabled rules, and adjusted profiles do not reuse old search hints automatically. Final review uses the frozen rule-coverage-v2 recipe. Shared preferences and any one applicable style group must satisfy limits.minStyleMatchRatio (default 0.75). If even satisfying every unknown rule cannot reach that ratio, the group is rejected; otherwise unresolved evidence stays pending review. This is rule coverage, not calibrated model confidence. Historical tasks and human releases retain their original recipes. Agent preparation discovers usages, source and limits; it cannot create human-owned usages.

The image-search skill and native launch message identify Visual Curator as the workflow owner. Preparation checks use visual_task_prepare; AFP tools belong to a separate photo service. A pinned launch uses its supplied profile, active rules and attachment without enumerating all styles or replacing the fixed version. The message includes the collection ID for targeted reads if further evidence is needed.

The optional tools row exposes bounded style reads, search/crop starts, run reads, Agent suggestions and export starts/reads. It exposes no human-confirmation, publication, default-switching or split-confirmation command. Long operations return task handles; a start acknowledgment is not a qualified-image result. Tool results contain safe identifiers and authorized resource references; auxiliary vision requests retain their actual image order, digests, prompts, model/version declaration and validated output in the plugin-owned run request journal. Session tool results identify that run; the bundle checks Session ownership before dispatch and does not write experimental Session records.

Tool declarations add to the model's tool-schema context while enabled. The bundle does not inject a style into every request or change Home instructions. Individual vision calls consume their own text and image budget. Native receipts retain provider-reported token usage; unavailable cache fields remain unavailable. Exact billing and gateway-wide cache statistics remain supplier-owned.

## Known Limitations and Deferred Work

<a id="known-limitations-and-deferred-work"></a>

Only configured image sources and image-capable native LLM routes or the compatible HTTP backup are supported. There is no arbitrary-site crawler, paid-original acquisition, image generation, segmentation, embedding/vector retrieval, model training or remote favorite write. The system reviews currently recalled candidates and cannot claim complete-library recall. Original quality, licensing, export permission and aesthetic usefulness require the user's own verification.

Keyless fixtures validate control flow and exact image geometry. They do not validate a real source/model deployment, vendor billing, broad visual quality or suitability of a user's references. Supply actual endpoints, response mappings, credential references, model capabilities and authorized samples before treating those properties as verified. Image-only evaluation leaves unsupported crop metrics unavailable. Profile locking coordinates processes on one machine; shared storage across independent hosts is outside its supported locking model.

From this plugin directory, `node scripts/test-preview-search.mjs` exercises the production Run engine, Unsplash adapter, review provider, storage, launch admission and observation logic with controlled source/model responses. It checks query rotation, mismatch rejection, cancellation, zero original downloads and original-output regressions without external services. The native browser fixture and its preview checks live in `tests/fixtures/build-search-feedback.mjs` and `tests/fixtures/preview-search-browser.mjs`.
