# 宇宙恒星球体迭代协议

## 目标

通过 AFP 的文字召回获得足够候选，再以预览像素做保守的壁纸判定。收藏夹目标不是“只要标题提到天文”，而是可以直接作为宇宙壁纸使用的完整画面。

## 召回分组

1. 行星、地球、月球：用于大球体分支；小月亮仍由视觉规则拒绝。
2. 太阳日冕、耀斑、日珥：避免裸 `sun` 与日食活动、鸟类、日出日落的语义污染。
3. 带 `planet` 限定的具体行星：避免 `Mercury` 等体育队/人名歧义。
4. 星云、星系、彗星、黑洞、Milky Way、star field、star cluster、starry sky、star trails：用于扩展天体与密集星场分支。
5. artist impression、exoplanet、digital illustration：用于补足可直接作为壁纸的宇宙艺术视觉；允许无文字的成品构图，拒绝信息图、示意图、标签、边框和拼贴。不要以 “illustration” 一词本身作为合格依据。
6. Hubble/JWST、supernova、quasar、event horizon、accretion disk：用于补足大球体之外的深空形成物；文字中出现 `telescope` 不应自动拒绝，仍由像素规则排除博物馆模型和望远镜设备照。
7. Orion、Carina、Crab、Tarantula、Vela、Cygnus、Magellanic 等命名深空对象：当默认查询已达到分页上限时，用作新的窄召回来源；必须先做 AFP 最小读请求，再以既有壁纸构图门槛筛选。
8. Horsehead、Flame、Pillars of Creation、Eagle、Helix、Ring、Rosette、Lagoon、Eta Carinae、Centaurus A 等第二组对象：只有在已通过决策的元数据中反复出现、且上一组来源已耗尽时才启用。将它们按精确名称做窄查询；不得因为名称相关而跳过像素级覆盖率、空黑背景或壁纸呈现校验。

空间站、卫星和轨道新闻不再作为默认专用查询：2026-08-10 与 2026-08-11 的复核均未得到合格壁纸，且常见设备主构图、展品和地景污染。其他深空查询中偶然出现的次要设备仍按像素规则判断。

AFP 对过长的连续 `NOT` 条件可能返回 GraphQL 错误。发生时，保留最稳定的服务端排除，其他已观察到的污染转移至 `metadataExclusions`；随后用最小读请求确认每个 query variant 可执行。

实测记录（2026-08-11）：第一组命名对象来源的 r09 在 100 张像素复核中通过 76 张；第二组来源的 r12 通过 78 张。两组均保持 `0.92` 天体置信度门槛与既有构图硬规则，说明提升来自更精确的来源，而不是放宽判据。

## 分页与审计

- 一批 100 指的是最多交给视觉模型的候选数，不是强制接收 100 张。
- 每个 query variant 轮询取页，不能让第一个查询占满一批。
- 宇宙类别同一规范化标题最多 1 张，防止连续太阳图、同源插画或同一星空图集占满收藏夹。
- 每轮保留候选清单、视觉决定和 refresh report；运行文件不得包含 token、cookie、签名 URL 或预览字节。
- 每批报告应至少包含：原始召回、页数、元数据拒绝、视觉保留、累计保留、短缺和是否耗尽。

## 已确认的拒绝模式

- 小月亮/小行星与大面积空黑背景。
- 人、眼镜、望远镜、手持产品、日食观测活动。
- 以城市、山地、树林、动物、岩石或水面为主体，星空仅是背景。
- 体育赛事、明星、Phoenix Mercury、Los Angeles Galaxy、鸟类逆光太阳、日出日落、科普道具、屏幕或海报。
- 大而单色、平面化的科学太阳圆盘：不是成品宇宙壁纸。
- 银河、流星与树林/山地/地平线组合：属于地面夜景风景，不属于本收藏夹。
- 稀疏小星系散落在黑底的深场或天文目录图：黑色空白过多，不属于密集星场。

AFP 水印、版权条、图片 ID、查看器控件和元数据页面 UI 只是预览叠层：必须忽略，只判断其下的图片主体。源图自身的文字、Logo、边框或拼贴仍然拒绝。

这些是搜索或构图拒绝依据，不可用来放宽 80% / 60% / 40%（密集星场为 75% / 40%）的像素阈值。
# 宇宙恒星球体迭代协议

1. 每一轮先读取上一轮的候选、决策和报告，并确认收藏夹已有图片与全部历史决策都进入排重集合。
2. 每个检索变体先做 AFP 最小只读请求；服务端只保留稳定的窄召回条件，长排除条件交由本地元数据预筛。
3. 正式轮以 100 个全新候选为一个审计批次。视觉调用可以在内部切片以避免超时，但候选、决策和报告必须作为同一批次落盘。
4. 只分析底层图片像素：AFP 水印、版权条、图片 ID、查看器控件和元数据 UI 都是预览叠层，不得影响决定。
5. 每轮只针对一个主要误召回类型调整查询、元数据排除或视觉规则；调整前补回归测试，测试通过后才继续下一批。
6. 完成视觉复核后先执行 collections dry-run，确认目标名称精确、私有且无重复；只有用户允许时才逐张串行 apply，并在写入后重新读取远端数量。
