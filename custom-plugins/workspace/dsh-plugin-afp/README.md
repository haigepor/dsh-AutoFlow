# dsh-plugin-afp

English | [中文](README.zh.md)

## Summary

An independent npm bundle for DSH profiles. Read tools, visual refresh, remote writes, six Skills and three workbench entry positions can be selected independently. Defaults enable all three Agent capability groups, all six Skills and the global panel; the settings entry and conversation tab start disabled. Remote writes still require a plan and explicit confirmation. All page positions show the same profile-owned tasks and reports. Closing a page or switching sessions does not stop a task.

## Install and develop

From this directory run `pnpm install --ignore-workspace --config.auto-install-peers=false`, `npm run build:client`, `npm test`, `npm run check`, and `npm pack`. Install the resulting tarball with `dsh plugin --profile web add <absolute-tarball-path>` or through Plugins → Add plugin. A local directory also works: `dsh plugin --profile web add file:D:/project/deepseek-harness/custom-plugins/workspace/dsh-plugin-afp`. Use this checkout's DSH: earlier published runtimes do not support the new featureConfig declaration.

After publishing a reviewed package with your npm account, users install `dsh-plugin-afp@<version>` through the same plugin page or `dsh plugin --profile web add dsh-plugin-afp@<version>`. Restart a running Host after updating an installed package when module watching is disabled; replacing package files alone does not reload its imported operations. Do not install it globally. The package defines no application bin. Source attribution and publication limitations are in [UPSTREAM.md](UPSTREAM.md).

## Directory reference

Root `index.js`, `execute.js`, `skill.js` and generated `client.js` are exported lifecycle entries. `config-schema.js` validates deployment settings. Host implementations live under `src/host/afp-*.js`; browser implementations live under `src/client/afp-*.js`; adapted protocol and category policy modules live under `src/vendor/auto-afp-img/`. `skills/` contains instructions and references only. Root `cli/afp-task.js` exports a DSH-managed task adapter calling the same Host service as the UI; `scripts/` contains package build/check scripts. Edit browser source and run `npm run build:client`, rather than editing generated client.js.

## Icon assets

`assets/icons/` contains the AFP logo and twelve feature SVGs. The manifest declares their file paths; Plugin Manager serves them as file URLs without Base64 in Web. Feature icons use CSS masks with the page's semantic color tokens, including dark themes. Missing images fall back to the feature category artwork.

## Configuration

Configuration editors reserve their loaded form height and show matching skeleton fields during the first read. Visual refresh uses account/authentication and model/budget columns on wide windows and one column below 760px. Fields sit directly on the dialog surface, grouped by headings and spacing. Content scrolls inside the editor; Save stays visible, including when Advanced expands. Read failures preserve the editor size and show an alert.

In the workbench's Visual model section, model settings and screening parameters share the left card with Save; Advanced configuration occupies the right card and starts expanded. Both cards use the AFP account layout's column proportions and matching heights, stacking below a container width of 860px. The JSON editor fills the right card and shares one draft and save action with the model fields; collapsing it or switching sections retains unsaved edits.

The packaged `config.json` is an initial template. The authoritative user file is `<profile>/.plugins/dsh-plugin-afp/config.json`, containing `version: 1` and a complete boolean `features` map. Plugin-page changes and manual edits use this same file. HMR watches it; profiles without HMR require a restart. Invalid files remain unchanged and produce an error; the last running configuration remains in place during a failed HMR read. A managed save that fails during activation restores the previous file and running choices. Explicit legacy row selections migrate on creation; subsequent startup and upgrades retain the user file. Renaming/removing feature IDs or changing file versions requires an explicit migration rather than overwriting selections.

Feature keys are `read`, `refresh`, `write`, `ui-settings`, `ui-panel`, `ui-conversation` and the six Skill directory names. The plugin page and workbench distinguish selected state from actual running state. Home/command-line deployment overlays remain higher priority. The root bundle toggle retains all choices. Removing one UI entry only removes that entry; disabling refresh/write cancels and drains corresponding jobs. There is no prompt-injection feature in AFP.

Credentials are resolved through the DSH credential service using `AFP_ACCESS_TOKEN` or `AFP_USERNAME` + `AFP_PASSWORD`, and `VISION_API_KEY`. Only reference names are configurable here, never credential values. Token cache remains in the credential provider. The configuration dialog enables Get token only after both AFP username and password are entered; it saves them, then reuses the runtime login flow to acquire or refresh the token. The button shows its spinner while the request runs, and acquisition does not return the token or write it to plugin JSON. An explicit eye-button action can reveal the saved credential. Set `visionBaseUrl` and `visionModel` on Cordis row `afp`; see [config.example.patch.yml](config.example.patch.yml). Endpoints, model settings, timeouts, limits and `pollIntervalMs` are deployment fields, not feature JSON. The legacy deployment `allowWrites` field is accepted for stored-run compatibility and no longer grants permission; the `write` feature row controls writes. Token-only account identity changes when its token changes; username-based accounts keep stable identity.

## Workbench and tools

`settings.section`, `sidebar.panellist` + `main`, and `conversation.view` are independent lifecycle registrations for one five-tab workbench. It reads account metadata, photo search/details, collection contents, runs and plan history through the authenticated Host API; image previews use an authenticated same-origin binary route and are neither persisted nor Base64 encoded. Unavailable profile fields remain unknown, shared or unclassified collections are read-only, and selected photos can be added to named private collections after confirmation. Refresh runs accept per-run target and confidence-threshold settings. New plans record their creation time; older plans display an unknown date. Existing Agent tool names and successful outputs remain compatible. Tasks belong to the current profile, and the conversation tab shows these same tasks rather than a separate Session queue. Build client changes with `npm run build:client`; edit source files, not generated `client.js`. Removing the global entry returns its selected panel to Conversation; settings/conversation navigation follows the host shell's fallback.

Search offers a local keyword menu built from the positive terms in the bundled search profiles, with curated Chinese aliases and category filters. Typing makes no AFP or model calls. Arrow keys highlight options; Enter fills a highlighted term, while Enter without a highlight submits the current text. Escape and outside clicks close the menu; composition Enter does not search. The search toolbar adds up to 120 selected photos to an existing writable collection. The dialog snapshots the batch, refreshes targets and requires explicit confirmation; existing memberships and live selections remain intact. Results distinguish added, already present, failed and unverified photos. Older Hosts show a completed count until reloaded. Uncertain writes are not retried automatically. Rebuild the client after changing keyword profiles; the package check rejects a stale generated catalog.

Search and collection pagination retain existing cards while appending card-sized skeletons inside the same responsive grid. Initial search and next-page loading have separate button states. A failed next page keeps its cursor or offset, and Retry requests that page rather than resetting the list. Successful pages merge unique photo IDs; empty or duplicate-only pages and repeated search cursors pause pagination. New searches cancel pending page reads and reset cursor tracking while preserving selected photos.

Existing tools remain available: `afp_status`, `afp_search_plan`, `afp_collections`, `afp_report`, `afp_plan_change`, `afp_refresh`, and `afp_apply`. Actual reads start with `afp_photo_search_start` (required query, language and limit; no cursor field), then continue with `afp_photo_search` using the returned cursor and unchanged query/language while hasMore is true. `afp_photo_details`, `afp_collection_list` and `afp_collection_items` read metadata. Search uses caption text and a supported language, not offline plan filters or automatic translation. Legacy first-page callers may still omit cursor; known invalid placeholders "0" and "?" fail locally, including repeated calls. The Agent directory excludes unnamed entries and reports meta.excludedUnnamedCount; unnamed member reads are rejected before fetching contents. Named shared collections remain readable. Member pages return nextOffset; null ends paging. Limits follow deployment pageSize. New reads return allowlisted metadata and meta.durationMs without media links; absent details return found:false. Tool errors preserve DSH error status and contain safe code, stage, message, action, retryable and durationMs fields rather than upstream bodies. Invalid cursors and rejected GraphQL queries receive fixed parameter guidance; unknown read failures give read advice without suggesting partial writes. Only explicitly retryable reads can be retried; do not repeat unchanged non-retryable input. Agent jobs belong to the invoking Session and use DSH approval. Page jobs belong to the profile. Page write previews return a one-time, expiring confirmation credential; confirmation is consumed before admission and is invalid after a restart or disabling writes. Both paths recheck account, exact private target names, complete remote membership and the referenced run before mutation. Plans are consumed before the first remote change. Writes are never automatically retried or rolled back; cancellation and failure may leave partial results. Read the retained report and inspect collections before creating a new plan.

The workbench fills the available height and retains its heading and scrollable tab row. Search keeps its toolbar above independently scrolling results and details on wide screens, and distinguishes an initial prompt, loading, empty results and retryable failures. Wide task, change and collection panes scroll independently with full-height dividers; narrow windows stack them. Screening setup groups category choices and rejects invalid quantities or scores before submission, with an inline explanation. Report loading and failure stay in the report region rather than substituting history. Task and change histories share row skeletons and project refresh controls. Changes separates setup from preview/history; expiry, warnings and explicit confirmation remain required before writing. Account & Settings uses the project segmented control, bordered credential/model groups and a compact identity/credit panel; switching sections preserves drafts. Screening parameters and deployment JSON start collapsed. Features use category grids, quiet runtime indicators and expandable descriptions. Inputs, Menus, Tags, tooltips and button spinners use project primitives and theme tokens. Entry/disclosure motion respects reduced-motion preferences. Saved-run resumption starts collapsed and image details retain complete screening reasons.

Account cards share a theme surface and equal height when displayed side by side; the save action stays inside the credential card. Advanced configuration expands from the right-aligned entry. Collection select-all reads every metadata page before updating the selection, supports cancellation, and preserves other collection sources when deselecting; it does not load every preview or expand gallery pagination. Failed reads leave the prior selection unchanged. The existing download protocol accepts up to 120 photos per batch, so larger selections disable download with a tooltip. The download edge control uses theme shadows and an SVG animation during active batches, respects reduced motion, and opens the project Menu on right-click or Shift+F10. Its task-page action requires the global workbench entry. Close glyphs use the project icon at 14px with 28px click targets.

## Content and recovery

The account section reads the Hub `user` query through the Host and displays identity, email, user/client IDs and `credit.amount` beside the credential form. Zero credit is displayed as zero; absent credit remains unavailable. Account loading and retry do not block credential editing. No administrator, purchase or download-history operation is called. Stored passwords and keys remain in the credential provider.

The collection sidebar lists named collections as compact project Button rows with folder icons, document counts and a shared hover/focus highlight. Read-only or shared permissions appear as Tags; writable private rows omit the repeated permission label. Initial selection skips unnamed entries. Its collapse control sits beside the filter and remains accessible when folded. Photo selection uses a small circular SVG check inside a project Button with a pressed state; it appears on selected images and on hover or keyboard focus, and never opens details. Gallery cards use equal 4:3 preview frames for loading, success and failure; images keep their original proportions without cropping, with necessary letterboxing. The selection drawer closes through the selection summary toggle and omits a duplicate header close button. On wide screens it fills the gallery height, with its heading and clear action fixed around an independently scrolling list; narrow screens retain a bounded stacked drawer. Row removal controls appear on hover or keyboard focus and stay visible on touch devices. Action tooltips use short localized labels with a capped width; full photo titles remain in accessible button names. Folding the drawer preserves selected photos. The selection summary combines up to three complete thumbnails, overflow and a count Tag into one drawer button; batch actions remain separate. The AFP Settings section hides the shell action footer to give the workbench more height. The photo browser excludes explicit non-photo `docClass` entries while retaining legacy entries without that field; write validation still checks every member. Gallery and details scroll independently, and Back to top appears after half a visible gallery height. Skeletons and image fades respect reduced motion. Clicking a detail preview opens the project Modal with focus restoration. Preview consumers hold shared raster Blob URL leases; the last consumer release revokes the URL. The Host negotiates JPEG/PNG/WebP/GIF, accepts matching raster signatures with generic binary MIME, and rejects HTML/SVG. Blocked CDN errors report only a hostname; verify that domain before adding it to deployment `previewCdnHosts`. Signed media URLs and AFP credentials never reach browser metadata.

Selections can span collections and retain each photo's source collection. Remove unlinks only the selected photo relationship; it never deletes the photo or collection. Copy and move require a writable target, and move verifies target membership before unlinking a writable source. Downloads list available AFP renditions and their costs, default to the highest free quality, and recheck both the balance and quote before requiring explicit confirmation of any paid total. Paid options require the `write` feature. If AFP accepts a purchase but does not return a confirmed delivery URL, the item remains pending and is never purchased again automatically. Files stream to a directory chosen on the AFP Host, with a configurable byte cap, sanitized original filenames, and collision suffixes. Profile jobs continue when the workbench closes or changes; stopping the Host stops them. The stored history omits directory paths, credentials and signed URLs.

The download dialog fills the available modal height, with independently scrolling quality and settings columns on wide screens and one scrolling column on narrow screens. The cost/action footer stays fixed. Compact photo rows show dimensions, size and price once, with full rendition quotes retained in each quality menu. Toolbar icons refresh quotes or apply the highest free quality, highest available quality, or an exact AFP quality label across the batch. Matching uses each photo's own rendition ID; unavailable or permission-blocked matches keep their existing selection and report the applied count. A batch change invalidates the reviewed quote and never submits a purchase. Thumbnails, per-photo quality choices, retryable failures, row skeletons and button spinners distinguish loading stages and respect reduced motion. Accepted downloads show a global notification with a progress action. A collapsed screen-edge control opens recent batch progress and cancellation; it remains available across workbench navigation and uses persisted Host counts. Escape or an outside click folds the card. Filename affixes stay folded until needed. A failed photo does not block other photos; an unreadable balance permits free renditions but blocks paid ones. Changing quality, filename affixes or destination invalidates the reviewed plan. Quote changes require another review and new spend consent. Unknown quotes display no numeric total. Final filenames use the delivered name when available; the preview uses the complete GUID/photo ID as a fallback, preserving dots in identifiers.

Six Skill rows hold independent process/profile leases under `$DSH_HOME/.plugins/dsh-plugin-afp/skills/`. The last holder moves owned content out of `$DSH_HOME/skills/` into a private inactive directory. Edits to owned content are retained and restored; same-name user content, damaged ownership markers, symlinks and conflicting copies are refused. Because the scan directory is shared, another profile using the same Home can still expose a Skill. Dead-process holders recover on the next lease operation. Existing Session history is not erased.

Run and plan UUIDs remain stable under `$DSH_HOME/.plugins/dsh-plugin-afp/profiles/<profile-hash>/`. Failed/cancelled visual batches retain pending candidates and cursors for resume. Home-wide account/run locks prevent concurrent operations; an incomplete lock or leftover recovery guard refuses work and requires inspection after stopping its owners. Reports contain counts and sanitized failure information, not credentials or preview bytes. Local run files still contain candidate metadata and should be treated as private data.

Download options and plans are bound to the Host account identity; changing accounts before preparation, confirmation or execution refuses the old batch. A changed quote uses one refreshed snapshot and always returns the choices for another explicit confirmation. Collection results include partial and unverified counts; account resets discard late operation responses. Startup failures and interrupted tasks finalize each unfinished item and keep aggregate counts consistent. Task failures expose fixed error codes rather than raw authentication or delivery errors.

## Preview cache

The plugin store owns a page-memory cache shared by gallery, detail, selection and download previews. Concurrent consumers share one request; successful raster Blobs use LRU retention. Deployment JSON sets `previewCacheMaxEntries` (default 300; 0 disables retention), `previewCacheMaxBytes` (64 MiB), and `previewCacheTtlMs` (10 minutes). Expiration is checked on acquisition, release and cache inspection. Entry/byte limits cover retained Blobs, excluding active images, DOM and decoded memory. A closing consumer cancels only its subscription; the last waiting consumer aborts the request, and the last URL lease revokes its object URL. Failed requests are not retained; decoding failures and explicit retries invalidate the matching version. Credential, read-access, connection and Host-scope changes clear previews and suppress late completions. Disposal drains owned reads. Browser refresh clears memory; no persistent files, signed media URLs, credentials, paid originals or quotes are cached. Host HTTP responses remain authenticated and `no-store`.

`node scripts/benchmark-preview-cache.mjs` compares six uncached and cached consumers with an offline 40 ms transport. It asserts request counts, not browser rendering speed.

## Verification

`npm test` uses simulated AFP interfaces and isolated temporary Homes; it performs no live AFP writes. The Session snapshot consumes repository `pnpm run build:lib` artifacts and explicitly skips in standalone copies without them; it records the real Agent loop calling offline search and tool removal after disposal. `npm run check` checks syntax, exports, defaults, shipped documents and UTF-8. Repository tests cover JSON selection migration, row toggles, manual HMR edits, activation rollback and legacy bundles. Packed-profile installation and browser verification use the built checkout. Simulated success does not establish production API availability, account permissions or image licensing.

## Feature information and configuration dialogs

The detail page shows feature type groups with inline disclosures and status tags; the component inventory is collapsed by default. Select a feature name to expand a concise description of its purpose, requirements and relevant effects in a muted inset block with expansion and collapse transitions. Script/tool edit controls open a shared configuration dialog using DSH Modal, Input and Button. Common model and budget fields are directly editable; Advanced settings holds full JSON. The saved username is displayed in its input. Configured password, token and vision key fields show a fixed-length mask and a success tag. Their eye buttons reveal a draft locally or read one saved value through an authenticated AFP-only action bound to the current deployment revision; a verified cached token is included. Normal configuration reads never return secrets, and viewing alone never writes them. Hiding, switching sections or saving clears revealed values; late responses after editing or closing are ignored. Failed reveals retain the mask and offer retry. Successful secret writes clear drafts and hide the fields again. Dialog inputs include their padding and borders in their width; responsive columns prevent clipping and overlap. All four fields save to DSH credentials under current deployment references; blank preserves existing values. Deployment JSON carries references, endpoints, models and budgets and saves/reloads through the profile editor. Deployment saves cancel active tasks; credential saves do not reload. Each save reports its own outcome; successful credential writes are not undone by a later deployment failure. Reopen after changing references before saving credentials.
