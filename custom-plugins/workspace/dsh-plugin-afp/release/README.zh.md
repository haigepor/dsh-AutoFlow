# AFP 版本发布

[English](README.md) | 中文

## Summary

从本仓库向 GitHub Releases 发布独立 AFP 包。包版本决定 `afp-v<version>` 标签；AFP 不与应用共用发布版本或 latest 标记。[release.config.json](../release.config.json) 负责维护仓库、标签前缀与稳定频道。完整执行和验证流程使用[发布 Skill](../../../../.agents/skills/dsh-custom-plugin-release/SKILL.md)。

## 准备源码

使用仓库要求的 Node.js 和 pnpm 版本、Git，以及具备目标仓库写权限的 GitHub CLI。阅读 [UPSTREAM.md](../UPSTREAM.md) 并保留来源记录；本流程不向 npm 发布，也不为适配的第三方代码推定许可证。审核待发布改动，为新版本更新 `package.json`，同步 README 双语对，并在准备正式资产前提交。不得覆盖已发布版本或移动其标签。

在仓库根目录准备已提交版本：

```sh
pnpm --filter dsh-plugin-afp run release:prepare --out .artifacts/afp-release
```

该命令运行 AFP 测试，通过 `prepack` 构建和检查包，验证 tarball 路径及声明入口，生成三个资产：`dsh-plugin-afp-<version>.tgz`、`SHA256SUMS` 和 `afp-update.json`。JSON 记录精确源码提交、标签、下载地址、SHA-256 与字节数。`--tag afp-v<version>` 校验指定标签。`--allow-dirty` 仅用于本地演练：元数据会标记脏树，发布器拒绝此类产物。

## 发布与验证

将审核后的源码和新 `afp-v<version>` 标签推送到配置的仓库。[AFP 工作流](../../../../.github/workflows/release-afp.yml) 从标签构建，校验包版本和源码提交，在无写入凭据的阶段准备产物，再由独立发布任务上传草稿。它按 Release ID 查找草稿，资产校验通过后才公开发布，并设置 `latest=false`。从当前工作流手动触发时，输入已有 AFP 标签，并构建该标签的源码。已有资产完全匹配时只复验，不替换；资产缺失或不同则停止发布。

工作流成功后，确认 Release 已公开、三个资产已上传且标签提交正确，记录链接、版本、来源提交及资产信息即可完成发布。默认不再次下载资产，不创建临时 profile，不安装或演练更新。用户明确要求回验，或发布、摘要及安装反馈出现异常时，才下载相关资产核对 SHA-256 和元数据；需要安装验证时使用支持的 `dsh` 启动器及隔离 profile，不覆盖正在使用的 AFP。

创建草稿后，发布器在最多 20 秒内重试查询 Release ID。草稿仍不可见时停止发布，不重复创建草稿或替换资产。核对源码及已上传字节后，可使用已有标签手动触发恢复。

## 更新与恢复

这些资产提供有版本的 GitHub 分发渠道。AFP 的 `dsh.bundle.update` 声明仓库、`afp-v` 标签族和 `afp-update.json` 资产；[插件管理器](../../../../packages/boot/plugin-manager/README.zh.md)默认自动检查，明确开启后自动下载安装，重启生效并保留配置。根目录 `pnpm install` 仍使用工作区与 lockfile。插件与桌面端分别发版，历史标签及 Releases 整理遵循[发布规范](../../../release-governance/README.zh.md)。

发布失败的草稿可在核对标签与已上传字节后检查和恢复；不得静默覆盖资产或删除无关 Release。已公开版本的问题通过新包版本和标签修正。保留旧 tarball，以及用户的功能选择、凭据和报告；包降级无法撤销不可逆的数据迁移。

## AFP 0.1.1

聊天反馈以行内折叠输出呈现视觉校验。已通过与未通过分为两个独立图片列表，最多同时显示五张缩略图，超过可横向滚动；放大预览复用工作台弹窗。本地预览、完成像素判断和请求失败分别计数。重复读取相同报告时合并摘要，工具检查器记录仍保留。不再注册重复的 AFP 输入区进度胶囊。

视觉 dry-run 持久记录准备阶段，反馈连接与收藏夹读取进度，各准备阶段使用配置的请求超时限制等待，并拒绝同一 Host 内对正在执行运行的重复续跑。六个 DSH Skill 在 AFP 操作前创建并维护任务清单，只有确需跨轮执行的大规模资源目标才考虑目标，已安装的用户自定义指引予以保留。最终选图仍需成功保存；读取预览或生成筛选报告不能代表最终图片已保存。

包保留既有配置及稳定更新来源字段，安装更新后重启生效。任务图标、悬浮宽度、队列动画和队列/目标共享顶栏属于 AutoFlow 应用源码改动；仅更新 AFP tarball 不会安装这些应用组件。验证使用无密钥会话快照、模拟 AFP/视觉提供方及隔离 profile，不代表生产 AFP 或真实模型视觉判断准确性已验证。

## AFP 0.1.2

本版本修复 Windows 检查点替换失败，使用有界重试并保留旧记录；macOS 仅允许系统 `/var`、`/tmp` 别名，不放宽用户目录链接校验。发布前在 Windows x64、Linux x64、macOS arm64 和 macOS x64 原生运行 AFP 回归，全部通过后才公开资产。

审核按图片保存结果和风景二次确认检查点，恢复时复用已完成判断。收藏夹读取与候选查询限制并发和预算；传输与响应体共享重试预算，避免重试叠加。Agent 可明确请求保留数量和至少完成的判断数量，数量不足仍报告未完成，不保存空选图冒充成功。

运行诊断保留当前审核尝试的总耗时、独立阶段耗时和脱敏失败位置；Debug 只增加有界详细事件。CDN 拒绝报告精确域名，核实后通过 `previewCdnHosts` 配置，不允许任意媒体跳转或向 CDN 转发 AFP 凭据。

工作台更新任务、报告、收藏夹变更历史与配置布局，提供诊断标签、阶段表格、运行标识卡片及日志导出。报告左键打开大图审阅、右键查看详情，支持键盘前后切换及已通过图片选取；保留自动审核结果，不提供人工改判。加入收藏夹使用局部毛玻璃弹窗并继续要求明确确认。应用侧任务旋转图标、固定宽度任务栏及更新加载动画需运行包含本次提交的 AutoFlow，插件包不会替换应用组件。

## AFP 0.1.4

报告列表沿用状态轮询同步已加载范围，自动刷新保留内容，手动刷新使用与报告行一致的骨架。报告支持选择、菜单和已加载范围批量操作。暂停持久保存可继续的检查点；删除将本地报告移至 profile 的 `archived-runs/`，不删除远端收藏夹。归档、续跑与确认写入共享运行锁，引用已归档报告的计划拒绝写入。

分类可绑定现有具名私有收藏夹，按 profile/账号保存；删除绑定保留远端收藏夹，明确解绑不会恢复默认同名匹配。旧账号报告没有绑定快照时续跑保持默认目标；显式绑定按收藏夹 ID 校验，改名后的新预览采用当前名称，旧预览仍受远端目录摘要检查。绑定变更使旧确认与计划失效。

工作台补齐报告侧列、标题固定、回到顶部、折叠任务设置、顶部工具入口及统一实色弹窗和 8px 遮罩。发布默认在工作流成功、Release 公开、来源标签及三项资产齐备后结束，不额外创建隔离 profile 或演练更新。验证使用无密钥夹具，不代表真实 AFP 写入或模型判断已验收。

Windows 发布回归使用 Bash 内建读取减少轮询中的额外子进程，外层执行预算覆盖宿主启动；草稿出现、缺失和 API 错误的重试次数、等待次数及退出状态仍逐项断言。
