# Saved plan fields

Automatic analysis saves the complete plan before human review. Do not save another plan unless the user requests changes. For an edit, copy inputHash and revision from article_image_report and pass both unchanged on every article_image_plan_page call, from offset zero through every nextOffset. inputHash identifies the analysis inputs; revision pins the particular saved plan because an edit may preserve inputHash. Concatenate fragment strings in order and parse the complete JSON. Offsets count Unicode code points; fragment is decoded text, not an independently parseable JSON document. A stale revision or changed inputHash requires a fresh report and a complete reread; never mix pages from different saved plans.

Call article_image_save_plan with the real id, the same revision used to read every page and the complete edited plan. Full plans include sourceHash, inputHash, rulesHash, model, coverage, understanding, brief, shots, shortfall and structural checks. Preserve frozen fields from the retrieved plan; never invent hashes or reconstruct them from a report summary. The brief has theme (string) and facts, subjects, scenes (nonempty arrays of strings). The tool schema owns accepted fields and sizes. Manually supplied text and legacy plans require a new rich-source capture and automatic analysis before new approval.

Each shot contains purpose (cover or inline), paragraphs (positive indices matching the bN block references), rationale, subject, action, environment, composition, lighting, colors, style, details, avoid, prompt and ratio. Evidence uses blockIds and assetIds; afterBlockId locates insertion, informationGoal states the distinct editorial purpose, and visualMode is conceptual or source-grounded. Include exactly one cover and at most twelve shots. sceneHash and promptSceneHash are Host-owned synchronization markers: preserve their returned values. Editing a scene makes the prompt pending synchronization; pass its zero-based index in the save call's syncPromptShots only after updating or explicitly confirming the final prompt wording. The Host computes the markers. No provider request fields are accepted.

The final prompt combines scene fields in the frozen policy's prompt language, default English. Explain relevance in rationale, not in the scene as visible lettering. Use avoid for unsuitable or misleading elements. shortfall records requested and actual counts with a reason when content cannot support the target. Structural checks cover fields, references, versions and coverage; they do not certify factual semantics. Human review is this phase's final action.
