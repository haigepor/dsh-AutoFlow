# 第一期验收标准

本文件是待实施行为的验收要求，不是通过报告。执行者在实现后为每项登记命令/场景、输入与版本、实际观察、证据位置及 PASS/FAIL/BLOCKED；缺少真实站点或模型条件时保留 BLOCKED。任务与要求的对应关系见 [任务清单](tasks.md)，设计选择见 [技术设计](design.md)。

## 1. 证据分层与通过条件

| 层级 | 能证明什么 | 不能替代什么 |
|---|---|---|
| OpenSpec 严格校验 | 变更结构、要求与场景格式有效 | 代码、运行和语义验收 |
| 单元/集成及 keyless 回放 | 解析、引用、版本、编排、失败处理和模型可见输出稳定 | 真实浏览器布局、真实模型理解质量 |
| 真实 Chromium 本地 fixture | JS/懒加载、资产、提取和完整 UI 的真实运行 | 未纳入 fixture 的公开站点能力 |
| 真实公开文章抓取 | 声明站点/模板的正文与原图结果 | 模型理解和提示词的语义正确性 |
| 真实分析模型与人工评估 | 主旨、事实、文图理解、图意和提示词可用性 | 任意站点/模型的普遍保证 |

所有自动路径的关键要求通过、浏览器与实际站点范围有证据、AC-25 人工语义验收通过，才能宣布第一期业务完成。测试必须同时包含有效输入和确实被拒绝的无效输入；只打印成功或只检查字段存在不算证据。文本/视觉理解可以消耗配置模型额度，第一期仅禁止真实生图及发布副作用。

## 3. 固定 fixture 集合

下面的 fixture 是实施时创建的内容类型，不代表仓库已经存在同名文件。多数测试在本机临时 server 使用确定的页面和请求障碍，通过测试专用注入策略仅允许本测试拥有的精确随机端口，不依赖站点时钟或测试间共享端口；各自拥有并清理浏览器、服务和临时目录。该策略不能从产品配置开启，也不能掩盖生产路径拒绝本机访问的断言。

| 集合 | 输入与预期重点 |
|---|---|
| F01 静态结构 | 标题层级、强调/链接、嵌套列表、引用、表头/单元格、正文 figure；两侧导航/推荐/评论不得进入正文 |
| F02 延迟正文 | 初始摘要超过最小长度，脚本后续加载正文与标记尾段；超时分支不能误报完成 |
| F03 图片 | 长 srcset、picture、data-src、noscript、滚动加载、重复 bytes 不同位置、署名、403/损坏/超限图 |
| F04 范围 | 同文章分页与下一篇文章链接同时出现，只有已识别分页可继续；未知边界和不支持图表需核对 |
| F05 限制与恶意数据 | 登录/付费/验证页、危险预览 HTML、原文提示注入、禁止 URL/redirect/资源 |
| F06 规则与输入 | 两版编辑规则、缺失文件、无效策略、同一来源不同业务备注、任务中规则变更 |
| F07 长文与多图 | 内容超过一页与单窗口预算，关键限制在尾段，图片跨章节；漏一个块/图即可使覆盖检查失败 |
| F08 生命周期 | 可控等待的提取/模型响应、双启动、取消后迟到响应、阶段提交前后断开和文件发布失败 |
| F09 旧记录 | 有/无正文、旧审核、失败状态、损坏记录以及迁移一半退出的 schema:1 状态 |
| F10 编辑审核 | 草稿与远端 revision 冲突、主体/最终提示不一致、规则更新但未采用、采用新规则后再次审核 |

## 4. 真实文章与人工语义标准

实施验收至少选择六篇获准访问的公开文章，覆盖实际声明支持的投放站点模板；集合包含长文、多语言、有图、无图、列表/表格、具体地点或数值限制等情况，同一篇可覆盖多项。每篇先由编辑确认正文范围、关键事实与图像清单，保存有权限使用的基准或可重验的摘要记录，不能只拿提取结果给模型自我评分。

| 维度 | 可接受结果 | 阻断失败 |
|---|---|---|
| 主旨与结构 | 覆盖实际主要章节与结论 | 仅根据标题、漏掉主要论点/结论 |
| 事实与限制 | 预先标注的重要事实有证据，数值/时间/对象正确 | 捏造事实、丢失改变含义的限制或错误引用 |
| 文图理解 | 实际图像输入覆盖清单完整，观察与图注分开 | 只看 URL/alt 却声称识别画面，编造身份/地点 |
| 配图价值 | 封面对应主旨，正文图分别传达相关信息 | 无关场景、机械逐图替换、凑数重复 |
| 提示词可执行性 | 主体/动作/环境/构图等清楚且与方案一致 | 依赖未提供的上文、字段与最终提示冲突 |
| 不确定性 | 缺口可见，概念示意身份明确 | 把生成场景描述成实际事件证据 |

每篇全部维度满足可接受结果且无阻断失败，才计为该篇通过；六篇均通过才能签收声明的样例范围。编辑可以提出风格修订，但重要事实错误、遗漏和无依据场景不能被风格满意抵消。记录采用/修改/退回及原因，后续规则变更对同一集合重验。该结果不证明已生成图片的视觉质量，因为第一期不生成图片。

## 5. 执行顺序与证据记录

1. 每个实现切片运行其聚焦单元/集成测试及 keyless 场景，失败先修复，不扩大无关测试范围。
2. 依据最终变更运行插件和 toolkit 所属测试、Client 构建、package check、相关类型/依赖/打包验证；命令由实施时实际 package scripts 确认，文档阶段不声称这些未来命令已经通过。
3. 有模型可见变化时更新所属 recorded-session；文档与配置变化运行相关仓库检查，按 pre-push Skill 选择额外检查，不默认运行整仓覆盖或平台矩阵。
4. 使用 `pnpm dsh web --patch apps/web/tests/pin-browse-picker.overlay.yml` 的受支持浏览器验收入口，准备隔离测试 profile，验证浏览器闭环与零生图请求；启动、退出和临时资源清理均留证据。
5. 配置就绪且获得真实模型调用授权后执行 AC-25。缺少凭据、模型能力或站点样例时记录 BLOCKED，不调用其他付费服务替代。

证据记录格式：`AC-ID | 运行命令/场景 | 输入/规则/模型版本 | 预期 | 实际 | PASS/FAIL/BLOCKED | 证据位置 | 未完成条件`。记录应脱敏，不保存令牌、Cookie、密钥或携带凭据的错误；模型图像输入属于分析，不能计为已生成/上传发布图片。

## 6. 本次方案文档的验证范围

方案阶段的校验只覆盖 OpenSpec 结构、相对链接、Markdown 段落、UTF-8/换行及修改范围。实施阶段的实际证据另见 [verification.md](verification.md)，不把旧纯文本测试或方案格式校验当作新功能通过。AC-25 按用户决定由用户执行 [manual-acceptance.md](manual-acceptance.md) 的真实语义验收。
