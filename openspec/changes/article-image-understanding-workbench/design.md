## Context

这是 L 级跨模块变更，实施沿 Research → Design → Implement → Verify → Review 推进。当前处于设计交付：用户已确认获取完整文章富文本与原图，按内容重新规划配图，自动理解并生成提示词，最后人工审核；真实生图留到后续阶段。

[插件 Host](../../../custom-plugins/workspace/dsh-plugin-article-image/src/host/service.js) 与 [工具包服务](../../../custom-plugins/workspace/dsh-plugin-article-image/article-image-toolkit/src/service.js) 分别实现抓取与记录。[当前数据定义](../../../custom-plugins/workspace/dsh-plugin-article-image/src/shared/contracts.js) 只有编号文本段落；[工具包渲染器](../../../custom-plugins/workspace/dsh-plugin-article-image/article-image-toolkit/src/render.js) 默认阻断图片。[页面](../../../custom-plugins/workspace/dsh-plugin-article-image/src/client/workbench.js) 通过复制指令交给用户会话分析，审核后没有生图执行器。

[AFP](../../../custom-plugins/workspace/dsh-plugin-afp/README.zh.md) 提供共享 Host 服务、真实任务进度、检查点与确认模式。其后台视觉提示在 JavaScript 中构造，不能把 AFP Skill 注册误认为后台提示文件执行。本方案复用服务和生命周期模式，另行明确文章规范的运行时加载。

## Goals / Non-Goals

### Goals

- 从现有公开 CSV 导入入口选择文章处理；抓取成功且质量合格后，无需复制聊天指令即可自动分析。
- 保留正文的结构、顺序、正文原图、图注与署名，提供受控富文本预览及本地图片读取。
- 以全文覆盖、事实证据、文图关系和有差异的配图目标定义理解质量，输出可编辑、可核对的方案。
- 让规则文件修改实际影响后续分析，冻结每次任务的有效规则，保持历史方案可追溯。
- 任务不依附页面；阶段、失败、取消和中断可见，已确认的方案绑定精确版本。

### Non-Goals

- 不接入图片生成、图生图、上传、发布、表格回写、定时调度或私有 Google 表格 OAuth；不要求改变现有表格访问权限。
- 不逐张替换原图，不以原图数量决定新配图数量，不复制 AFP 图库及收藏夹功能。
- 不承诺任意公开站点都能完整抓取，不绕过登录、付费或人机验证；不把静态文本回退称为完整富文本。
- 不增加跨日/跨表格全局去重，不调整现有来源身份规则；重复导入保留现有正文与方案，只有明确处理/重跑才产生分析请求。
- 不更改 DSH 全局控制文件、模型协议、agent-loop 或公开 Session 格式；本次不编辑运行时 Skill，只在变更目录定义其后续要求。

## Decisions

### 1. 单一业务所有者与可复用提取内核

插件 `ArticleService` 负责导入记录、文章快照、任务、分析结果、计划和审核。工具包提供不拥有业务状态的 ESM 提取入口，输入已验证 URL、完整配置和取消信号，输出快照候选、资产候选和诊断。插件不启动第二个 MCP 服务来同步两份 `state.json`；现有独立 MCP 保留其适配用途，消费同一提取代码。

选择正式的 `article-image-toolkit` 库导出和生产依赖，显式将其加入必要的 workspace、锁文件与应用打包清单。模块内部不得引用仓库相对位置。沿用受支持的 `dsh` profile 启动应用，不新增应用启动器。实际 tarball/安装环境必须同时验证提取入口、依赖与 Chromium 就绪；开发目录可运行不能替代分发验收。

### 2. 文章快照以正文块为权威数据

以下为待实现的逻辑记录，不是当前代码已接受的字段。跨模块标识按仓库约定使用品牌类型，外部输入、持久记录和模型 JSON 在各自解析处校验。

| 记录 | 主要字段与含义 |
|---|---|
| `ArticleSnapshot` | `snapshotId`、`schemaVersion`、`requestedUrl`、`finalUrl`、`title`、`language`、`capturedAt`、`extractorVersion`、`sourceHash`、`blocks`、`assets`、`quality` |
| `ArticleBlock` | 稳定于本快照内的 `blockId`、顺序、`heading/paragraph/list/quote/table/figure`；文本行内保留强调与安全链接，图块引用 `assetId` |
| `ArticleAsset` | `assetId`、出现位置、公开来源 URL、本地引用、内容哈希、MIME、字节数、宽高、alt、caption、credit、状态和安全错误码 |
| `AnalysisInput` | `inputId`、快照与 `sourceHash`、分类/语言/备注的完整有界副本、规则快照、模型选择与参数、分块方案、实际图像输入清单、`inputHash` |
| `AnalysisResult` | `analysisId`、`attemptId`、`inputHash`、全文覆盖清单、理解稿、事实与图像证据、疑点、结构校验结果 |
| `ImagePlan` | `planId`、`revision`、`analysisId`、`inputHash`、整体风格、`shots`、检查结果、`planHash` |
| `WorkflowRun` | `runId`、文章 ID、`attemptId`、开始版本、阶段/状态、检查点引用、真实计数、时间、错误、关联 Session 与提交结果引用 |
| `ReviewRecord` | 方案 revision、`sourceHash/inputHash/planHash`、确认时间和工作台确认来源；不含任何生图授权 |

`sourceHash` 覆盖正文语义结构、顺序、图片内容哈希和文图关系，不含抓取时间、缓存路径或临时签名 URL。仅图片内容变化也会改变哈希；相同内容的 URL 查询签名刷新不会单独触发失效。旧 `paragraphs` 如需过渡，由正文块派生为只读投影，不双写两套正文。

索引、不可变快照、分析/计划/运行记录和图片文件分开保存，置于原有 profile 私有目录。图片不得以 base64 塞入索引；读取凭不透明 ID 解析，拒绝调用方提供磁盘路径。原子文件发布、引用提交和崩溃恢复必须保证索引不会指向半写文件；孤立临时资产延后按受控清理策略处理，不在迁移时删除旧记录。

### 3. 浏览器提取、原图和质量判定

第一期自动流程以浏览器渲染为正文来源。保留静态抓取用于诊断或明确标识的旧入口，不以其成功长度代替浏览器质量检查。使用独立非持久 context，不复用用户日常登录 profile；浏览器不可用时报告前置条件失败，不自动安装或静默降为纯文本。

在剪枝前收集正文区域及图片候选，处理 `img/currentSrc/srcset/picture`、常见 `data-*` 懒加载和受控 `noscript` 回退，排除广告、图标、头像和跟踪像素。候选按正文位置保存；相同图片字节可复用本地资产，但保留每个出现位置和独立图注。原图指页面公开提供的最高可用来源，不承诺获得站点未公开的摄影原文件；实际来源与降级原因必须可见。

对正文区域进行有预算的滚动、加载等待和已识别的只读展开；仅站点适配器识别的同一文章分页允许继续获取。禁止无限滚动进入其他文章、提交登录表单或点击访问验证。通用提取兜底保留未知诊断；站点适配器的 fixture 对照正文尾段、块序列、表格关系、图片数量及顺序。

图片下载设置逐图与整篇数量/字节预算、超时和并发，验证 MIME、可解码性及尺寸，逐张记录失败。超限或损坏不静默省略。CSS 背景图、SVG/canvas 图表和交互内容仅在适配器提供安全栅格化/提取支持时计入；检测到承载正文信息但不支持的内容进入待核对。视频与音频不作为本期完整提取对象，包含其独有信息的文章同样提示限制。

页面导航、重定向、数据请求及资产读取沿用已有公开 URL/网络访问策略，浏览器接入不得扩大到内网、本机或文件协议。真实浏览器本地 fixture 仅通过测试专用注入策略允许该测试拥有的精确随机端口，不作为产品配置、不放宽生产策略；同一测试集合还需验证生产路径拒绝本机目标。来源 HTML、链接、备注和图片属于数据，预览移除脚本、事件属性、危险 URL 和站点样式，模型不能据其改变系统规则或调用额外工具。

质量分为 `passed/needs-review/partial/failed`，每种结果都有证据和原因。`passed` 要求存在有效正文、无已知缺失/访问限制、全部正文图片已获取，并且完成所选适配器的检查；它表示已通过声明的检查，不保证识别了未知站点的全部缺失。未知提取范围、分页未处理、懒加载未就绪、正文截断或正文图缺失不自动分析。编辑可登记核对范围与依据，通过明确的“核对并开始分析”动作启动后续模型阶段；仅打开核对页不触发请求，已知缺失仍须补齐，不能只点击按钮清除。

### 4. 规则文件有明确加载入口和版本

现有 workflow Skill 负责工具顺序，editorial Skill 负责指导；共享领域规则放在其 `references/`，专用分析流程也显式加载同一份内容。[规范草案](editorial-guidelines.md) 是本变更的设计输入，实施时拆入包内规范与模板，不把 OpenSpec 文件作为运行时依赖。

规则来源顺序固定：包内事实与安全规范 → 包内编辑默认值 → profile 明确配置的可选编辑规则文件 → 本次任务显式选择的数量/比例。业务备注为来源数据，不能覆盖事实规范、审核要求或第一期无生图限制。不存在的已配置文件、无效字段、越界值或版本冲突使任务准备失败，不静默忽略。

每次任务读取完整文件内容和机器可读策略，保存文件身份、顺序、规范版本与内容哈希；稳定快照形成 `rulesHash` 并进入 `inputHash`。任务期间文件修改不影响在途输入；新任务读取新版本，历史方案显示所用版本与是否落后。明确重分析才采用新规则并使原审核失效。

为保持使用连续性，初始可配置偏好沿用中文解释、英文最终提示词、16:9、一张封面与两张正文图。数量为目标，且继承现有上限；不足以支持所需数量时返回缺口与解释，不能凑图或自动审核。用户可以按文章修改目标，不以原图张数决定新配图数量。

### 5. 专用分析会话与可检查的理解结果

每篇文章任务使用插件拥有的独立 DSH 分析会话，复用宿主模型配置、附件、工具、会话日志与取消机制。使用 profile 显式配置的分析模型选择；有原图时要求所配置路线支持实际图片输入，否则进入待配置，不能声称已完成原图理解。模型参数、上下文预算、图像输入预算及可接受的生成参数由配置解析，不依赖某个恰好打开的聊天。

专用会话只开放本任务正文/资产读取、阶段结果提交和最终方案提交等必要工具，不开放 shell、任意文件写、插件管理、审批或生图。正文、图片输入及有效规则通过常规持久消息、附件、系统提示和工具结果进入模型；必须从会话日志和持久附件重构，不能只在插件记录中保存摘要后直接调用隐藏 HTTP 模型接口。

分析按理解稿 → 配图规划/提示词 → 检查提交推进，不强制短文产生多余模型调用。长文按章节和上下文预算划分，记录全部正文块与每张原图的输入/处理覆盖，分块后必须完成全文综合；实际发送的图像可采用有界衍生图，记录其内容哈希、尺寸和原资产对应关系。超过总预算进入有原因的待处理状态，不截断后宣称读完。模型“看过”只表示请求确实包含该输入，语义正确性由证据和评估检验。

理解稿包含文章类型、受众/目的、主旨、章节结构、关键实体与事实、限制条件、疑点及文图关系。事实与配图决定引用当前快照的块/图片；输出结论和证据，不收集或展示模型内部思维过程。自检分成代码可验证的覆盖/引用/字段检查与需人工判断的语义项，不能把自评分当事实正确保证。

按 [异步生命周期规则](../../../docs/defensive-patterns.md) 独占每次尝试的会话驱动区间，绑定持久输入 receipt、`attemptId/inputHash` 和专用提交结果。只有对应结果通过校验并落盘，阶段才完成；`whenIdle()`、模型结束文字或 Job 返回句柄均不是方案完成凭据。

### 6. 自动推进、互斥、进度和恢复

手动导入继续只创建/更新来源记录。用户点击单篇或批量“处理文章”后启动提取；现有抓取入口升级为明确标识的“获取并分析”。质量合格时 Host 自动入队分析，不需要用户发聊天指令。未变化且已有有效方案的文章默认复用，重新获取/分析必须显式操作；重新导入本身不触发费用。

| 状态 | 可观察结果与后续 |
|---|---|
| `queued` | 已持久排队；未开始不显示完成计数 |
| `capturing` | 获取正文与资产，暴露真实数量 |
| `needs-source-review` | 质量需核对或内容待补充；不调用分析模型 |
| `waiting-config` | 浏览器、模型或图像能力缺失；保留就绪诊断 |
| `understanding` | 输入覆盖与理解稿处理，生成中使用不定进度 |
| `planning` | 编写差异化配图和最终提示词 |
| `checking` | 检查覆盖、引用、数量、完整字段及语义疑点 |
| `review` | 当前完整方案待人工审核 |
| `approved` | 人工确认精确版本；本期终态，不产生外部副作用 |
| `failed/cancelled/interrupted` | 保存失败阶段与已提交检查点，明确重试/恢复入口 |

任务阶段与文章当前有效方案分开记录，失败重抓保留旧预览，但不能把旧方案当本次成功结果。每篇最多一个有效写任务；跨进程用现有锁/原子提交能力，写入检查有效 `attemptId`、开始版本和输入哈希，取消、重抓、人工修改或重分析后的迟到结果不可覆盖当前记录。

Host 用现有 Jobs 承载任务，持久运行记录是页面重开/重启后的状态依据。状态接口返回阶段、开始时间、真实计数和安全错误，不从动效计时推算理解百分比；Client 沿用有界轮询，不新增必须维护的传输协议。关闭页面只结束订阅，停止任务才取消；停用分析能力/卸载会取消并等待模型、浏览器、文件写入和监听器退出。

Host 异常退出后把未结任务呈现为 `interrupted`，不自动重发模型请求。用户显式恢复时沿用已冻结输入和已完成阶段；没有提交完成凭据的阶段重新尝试并记录新 attempt。模型网络结果不确定时保留该事实，说明恢复可能再次消耗模型额度，不承诺提供方未支持的 exactly-once。

### 7. 工作台审核与第一期终点

保留当前侧栏与标签页结构，正文页显示有序富文本、原图、质量与失败位置；理解页展示主旨、事实及块引用；配图页展示位置、表达目的、场景参数、最终提示词和检查项。点击引用可定位正文，点击原图显示本地资产。窄屏按阅读顺序堆叠，状态变化通过可访问状态区播报，并遵循减少动态效果设置。

所有页面文案通过现有 locale；使用共享 primitives，不增加第二套组件体系。Host 提供状态和版本，页面提供取消、明确重试/重分析、编辑、保存和人工审核。保留现有未保存修改提示，轮询不覆盖草稿；修改场景字段将最终提示词标为待同步，禁止带不同步提示词的方案审核。Host 用场景字段摘要与提示词所对应的场景摘要跟踪过期关系；重新编写，或编辑明确确认同步后保存，才能绑定当前场景版本。这项检查只保证同步动作对应当前版本，画面语义一致仍由模型检查与人工审核判断。

审核仅由明确的工作台动作提交，Agent 工具与专用会话不提供批准入口。Host 校验方案 revision、来源、分析输入、方案哈希、质量状态及同步状态后原子记录审核。手动修改理解稿的事实/引用必须重新检查依赖配图；修改提示词不要求重读全文，但保存仍清除旧审核。

文章正文/参与分析的原图、已采纳的业务字段、理解稿或配图内容变更，或者任务采用新规则/模型参数，都会使原审核失效。与分析无关的来源行号变化不使方案失效；全局规则文件更新不篡改已冻结的历史方案。第一期没有生成 action、tool 或 provider，`generation.available` 保持 false；审核完成、批量、重试与恢复均不得发送生图请求。

### 8. 配置与边界

沿用现有大小、抓取并发与轮询配置；新增并校验浏览器/滚动预算、图片预算、分析并发/上下文预算、模型选择、规则文件及编辑偏好。新增参数仅在所属解析器统一 resolve，不在执行方法隐藏默认。首次部署保持保守分析并发，UI 展示缺失模型/浏览器的明确配置入口。

当前公开 CSV 与手动导入是本期入口；私有表格返回原有授权限制说明。禁止要求用户公开原本私有的数据。旧功能开关保持兼容，必要时新增独立分析开关；UI 与工具/分析能力分别管理，关闭页面入口不取消后台任务。

## Risks / Trade-offs

- 通用浏览器提取无法识别所有正文缺失 → 维护声明的站点/fixture 支持范围，未知内容进入核对，不承诺全网完整。
- 原图体积和视觉额度高 → 独立资产存储、可配置预算、可追溯衍生图；不默默丢图或暗中降级。
- 事实引用存在但语义不支持 → 机器校验与人工标注语义评估分开，不能仅靠 JSON 有效或模型自检验收。
- 引入独立会话增加任务与日志资源 → 限制并发和工具集合，任务结束释放 live handle，保留持久输入和结果。
- 浏览器依赖导致源码成功、安装失败 → tarball 生产安装测试及浏览器就绪/缺失两条验收；不把浏览器二进制隐式塞进包。
- 兼容旧记录需要迁移 → 原文件只读备份、验证后原子发布，不把旧纯文本/批准冒充新格式有效结果。

## Migration Plan

1. 实施前读取当前工作区与用户改动，保留现有接口和 fixture 作为回归依据；本次文档不迁移任何数据。
2. 为插件自有 schema:1 设计单向 successor，验证旧文件并保留不可变备份，构造新索引和快照引用后原子提交；异常重跑可检测已完成步骤，损坏记录失败退出且保留原件。
3. 保留旧文章 ID、来源、文本、旧方案和历史审核，标记 `legacy-needs-refetch`；旧数据可预览，但不满足新完整提取、分析或审核前置条件。显式重抓成功后产生新的规范化快照。
4. 同一实现切片更新 Host、Client、原生工具、独立 MCP 相关消费者及 README/JSDoc。外部可感知不兼容行为立即增加所属 upgrade guide；只有实际触及已声明持久类型时按仓库规则登记，不擅改 Session 版本。
5. 用空 profile、旧记录 profile 和生产安装产物验证后再交付。回退先停止任务并另存新数据，旧包只读取保存的旧格式副本；不宣称旧包能打开新格式，也不删除新快照或覆盖既有 Session 文件。
