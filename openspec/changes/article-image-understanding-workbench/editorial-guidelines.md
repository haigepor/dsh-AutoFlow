# 文章理解与配图提示词规范草案

本文件定义第一期的领域要求与提示模板，供实施时沉淀为插件内 Skill references、运行时模板和可编辑规则。它不是当前已经安装的 Skill，也不作为生产运行时文件。流程、输入冻结和配置优先级见 [技术设计](design.md)，行为要求见 [分析能力规格](specs/article-image-editorial-analysis/spec.md)。

## 1. 规范与文件的归属

| 计划中的文件/资源 | 内容 | 执行方式 |
|---|---|---|
| 现有 `article-image-workflow/SKILL.md` | 状态检查、处理与恢复、按快照读全文、保存待审核方案 | Agent 按需读取，不能代替后台任务启动器 |
| 现有 `article-image-editorial-prompts/SKILL.md` | 理解、配图、事实约束和校验流程 | 引用共享领域规范，不重复完整数据 schema |
| 包内 editorial Skill 的 `references/understanding.md` | 本文第 2、3 节的理解标准 | Skill 和专用分析流程显式读取同一内容 |
| 包内 `references/visual-planning.md` | 本文第 4、5 节的配图与提示词标准 | 编排模板按阶段加载 |
| 包内运行时模板 | 理解、综合、配图、检查的任务指令 | 读取模板与冻结规则后通过 DSH 持久消息/工具结果进入模型 |
| profile 自有编辑规则 | 行业、读者、风格、图数、比例、品牌限制等 | 经配置指定和校验；新任务读取，旧任务保留快照 |
| 所属测试与人工标注样例 | 正反例、事实依据、不能接受的视觉推断 | 分别用于 keyless 回放和真实语义验收 |

机器可读 schema 由代码拥有，提示模板通过受控渲染引用其约束，避免 Skill、Host 与模板分别维护三份字段定义。任何文件加载失败都应报告其归属与修复方式，模型不自行读取任意磁盘路径。

## 2. “理解文章”的输出标准

| 项目 | 必需内容 | 检查方式 |
|---|---|---|
| 文章定位 | 类型、受众、写作目的、语言、中心观点 | 与标题及全文相符，不能仅重复标题 |
| 内容结构 | 章节及其核心信息、前后关系、结论 | 覆盖全部正文块；长文保持章节与全文综合关系 |
| 关键事实 | 人物、机构、地点、时间、数值、条件与因果陈述 | 每项引用支持它的 block/asset；原文主张与已观察事实分开 |
| 限制与疑点 | 时效、适用对象、缺少依据、原文歧义和矛盾 | 不把推断写成已证实事实，不抹去限制条件 |
| 原图理解 | 可观察主体、动作、场景、图注关系和信息作用 | 记录实际送入模型的图像输入；无视觉输入不能声称看过 |
| 配图机会 | 哪些信息适合视觉表达、为什么、建议位置 | 依赖理解稿与正文证据，避免给每段机械配图 |

标题、正文和图片同等按来源数据处理。原图中无法确认的人名、地点或数值，不因图注的语气而被当作视觉可观察事实；图注是独立文本证据。不要把公开文章改写成额外事实，也不要在线搜索补充事实来掩盖提取缺失。

长文采用章节分块、各块结构化理解和全文综合。覆盖清单表达“已送入/已完成该块分析”，不表达不可测的认知程度。最终综合必须检查跨章节重复、限制和结论是否遗漏；原图数量超过单次输入预算时按原位置分批处理，不以取前几张代替全部。

## 3. 理解阶段提示模板草案

以下是待实现模板的语义内容，动态值必须来自当前任务冻结输入；原文放在明确的数据区域，不能与系统规则拼接成同级指令。

```text
任务：分析当前 articleSnapshot，产出可用于编辑配图的文章理解稿。
输入：已冻结的正文块、原图/衍生图清单、业务分类与备注、编辑规则、输出 schema。

1. 阅读本阶段分配的全部正文块与实际提供的图片；输出覆盖的 blockId 和 assetId。
2. 说明文章类型、读者、写作目的、中心观点和章节结构。
3. 提取关键事实、实体、时间、数字及其限制；每项提供当前快照的来源引用。
4. 区分原文明示、视觉可观察内容、编辑解释和无法确认的信息。
5. 说明每张原图与附近正文的关系；没有实际图像输入时只报告已提供的元数据。
6. 列出疑点、矛盾和不能直接视觉化的内容，不通过猜测补齐。
7. 此阶段不写最终生图提示词，不申请生成、上传或发布图片。
8. 按 schema 提交理解结果；缺少输入或引用时提交明确缺口，不声称已读完全文。

输出简洁理解结论、证据与疑点，不输出内部思维过程。
```

全文综合模板使用全部已提交分块结果、来源块索引及必要的原始上下文，检查全覆盖后合并理解稿。不能只拼接摘要或把第一块结果当全文理解。

## 4. 配图规划标准

每张配图必须回答：表达文章中的哪个信息、给读者增加什么理解、放在哪里、由哪些来源支持。封面表现文章的主要主题；正文图分别承担不同信息，不为了达到目标数量重复主体与场景。

先定义图的编辑目的和真实性级别，再确定主体、动作、环境与视觉处理。具体地点、建筑、产品外观、人物身份或事件现场仅使用来源支持的细节；来源不足时选择明确的概念示意并记录限制。医疗、财经和新闻中的概念画面不能被描述为真实证据照片；文章数值不能随意变成看似真实的图表。

风格由规则决定，可采用写实摄影或合适的编辑插图；不把“所有文章都使用同一种图库场景”写成不可改规范。整组图片保持主题、色彩和视觉尺度协调，同时避免近似重复。原图用于理解与核对，不要求仿制、逐张替换或照搬其构图。

默认偏好是可编辑的一张封面、两张正文图、16:9，中文说明和英文最终提示词。只生成有来源支持且互有区别的图意；不足目标数时记录 shortfall 和理由。结构有效且事实检查通过的较少张数方案可进入人工审核，但页面必须显示缺口，不能声称已满足原目标。

## 5. 最终提示词标准与模板草案

| 信息 | 要求 |
|---|---|
| 主体与动作 | 单一清晰视觉中心，动作合理，必要的数量和状态明确 |
| 环境与细节 | 与文章有关、可形成画面；具体细节有来源或标注为概念选择 |
| 构图 | 景别、视角、前后关系和主体占比，避免多张场景挤入同一画面 |
| 光线与色彩 | 支持文章语气，与整组风格协调 |
| 风格 | 说明摄影或插图方式，不用通用质量形容词代替具体设计 |
| 避免项 | 误导事实、无依据标识、不需要的文字、水印或不合适画面 |
| 来源与位置 | 保存在结构化方案中，最终提示词无需包含全文或内部编号 |

```text
任务：根据已通过覆盖检查的文章理解稿，规划配图并编写独立可执行的提示词。
输入：冻结的文章来源、理解稿、实际原图分析、编辑规则、数量与比例、输出 schema。

1. 先确定封面主题和不同正文图的信息目的，再写画面。
2. 每张记录来源 block/asset、建议插入位置、编辑理由及事实/概念属性。
3. 明确主体、动作、环境、构图、光线、色彩、风格、细节与避免项。
4. 按冻结规则指定的最终提示词语言整合上述场景字段，默认英文；解释与理由按冻结规则指定语言，默认中文。
5. 最终提示词必须自足，不能依赖“参照上文”“图一”或整篇文章才能理解。
6. 不把理由变成画面上的可见文字，不添加来源未支持的地点、产品或事件细节。
7. 不为凑图重复概念；数量不足时报告缺口，保留可支持的方案。
8. 按 schema 提交方案并等待人工审核，不调用任何生图或发布能力。
```

避免项保持编辑约束，本期不加入提供方私有参数，也不假设存在 `negative_prompt` 等服务字段。修改场景字段时旧最终提示词进入待同步；更新最终提示词并保存后才能审核。

## 6. 检查与人工审核清单

- 覆盖：所有正文块、原图和分块综合均有对应输入/结果记录，无预算截断被当作完成。
- 事实：每个重要事实与具体画面细节有依据，数字、时间和限制条件保持一致。
- 配图：封面对应主旨，正文图有不同用途和位置，数量缺口明确，原图未被机械仿制。
- 提示词：画面自足、场景字段一致、避免项合理、语言和比例符合当前规则。
- 审核：所有阻断问题已解决，当前源/输入/方案版本一致，人工确认不会触发生图。

机器检查负责字段、引用、覆盖、版本和输入预算；编辑或有标注的评估负责事实语义、配图价值和风格判断。模型自检只能提出结果和疑点，不能自行签发“理解正确”结论。

## 7. 评估沉淀

将漏段、误读、无依据细节、近似重复和人工大幅改写的原因整理为匿名化正反样例。每次规则改动对同一固定语料比较事实支持、覆盖、图意差异和人工修改量；不能仅比较提示词字数、JSON 格式或模型自评分。样例、检查项和失败判定见 [验收标准](acceptance.md)。
