## Context

AFP Skill 要求读取真实预览、账户收藏夹去重、本地分类规则及风景二次确认。现有 refresh 工作流已执行这些检查，最终选图也校验本轮报告证据；聊天反馈只显示调用名称，未利用保存摘要。后台请求失败被记录为决策，但不能等同于成功的像素判断。思考行关闭时设置固定高度，压缩记录则直接卸载正文，两者绕过已有 AnimatedCollapse 的退出过渡。

## Goals / Non-Goals

目标是提供清晰、可信、可恢复的 AFP 过程反馈，并修复聊天折叠过渡。保留当前主题、工具和原始检查记录，不新增第三方组件、不显示隐藏推理、不修改分类规则或自动写入收藏夹。

## Decisions

1. Host 摘要新增成功判断数量、视觉淘汰数量和固定类型的淘汰计数。保留 reviewed 的旧语义；请求失败单列，不输出原始供应商错误、媒体地址或任意 reason 文本。历史记录从既有 decisions 计算，不需要迁移。
2. AFP 自有 toolview 沿用“思考”的行内 DisclosureRow，不使用卡片背景或边框。默认收起，单行摘要显示真实预览数、完成判断数或保存报告计数；展开后摘要继续显示计数，已通过与未通过分别使用独立图片折叠行。后台启动行只轮询当前会话、当前轮、当前 callId 的认证进度；关闭轮次、卸载或终态时停止。连接失败保留最近真实计数并明确标示，不假装任务成功。保留通用 job 工具记录，避免接管其他插件的后台任务。
3. 同一轮相同参数、相同摘要的报告读取合并显示；不同结果继续显示，原始 Session 数据不变。最终选图继续由成功 afp_photo_selection 决定，元数据选图明确标记未视觉校验。
4. AFP 不注册输入框上方的独立进度胶囊，保留原生任务清单与聊天行内反馈。思考行取消立即锁高，压缩记录使用共享 AnimatedCollapse；减少动态效果、关闭 inert 和快速反向操作由现有组件统一处理。
5. 标题为“视觉校验”，带已知分类。计数与请求失败集中在摘要，展开后继续可见；不重复展示计数和说明段落。保存状态、类别目标和最终选图含义保留在摘要提示中。实时行展开后将当前阶段与大于零的待判断数量合并为一行，复用 TextShimmer；仅在任务运行、连接正常且展开时播放，完成、失败、停止、断线、收起或轮次闭合后停止。收起时阶段文字显示在摘要，展开时移到正文，避免重复；收起时标题流光，展开后标题静止，正文阶段行独占流光。窄屏摘要省略显示，提示保留全文。
6. “已通过”和“未通过”是两个独立、默认收起的图片折叠区，不合并为一个过滤列表；展开后各自显示横向多张缩略图，最多同时显示五张；窄屏减少可见数量，超出部分可以左右滚动查看，完整结果不裁剪。开关互不影响。分类仅使用原调用保存的逐图结论或后台批次落盘后发出的结果；请求失败与尚待判断的图片都不进入未通过列表。历史结果缺少逐图结论时提示未知，不能显示虚假的零数量或读取后来变化的报告补齐。认证完整结果和实时进度保留安全身份、标题、分类、判断状态及固定原因代码；这些界面字段不进入模型工具文本或任务输出。可见缩略图按需读取认证缓存并支持重试。聊天与工作台共同使用 PreviewModal，保持相同尺寸、contain 显示、失败重试、Esc 关闭与焦点恢复，不增加聊天专用弹窗样式。

## Risks / Trade-offs

六个可独立启用的 AFP Skill 分别声明 DSH 任务跟踪说明：执行操作前先用 todo_write 创建简短清单，依据报告和成功选图更新，不因后台任务返回句柄而完成清单。普通单轮任务不调用 create_goal；仅大规模资源目标且确需跨轮执行时考虑目标，遵守运行时权限并保留已有目标。规则由加载的 Skill 引导模型，不新增 Host 自动写清单或目标的机制；自定义 Skill 不覆盖，已知旧版说明通过摘要记录升级。

原生任务记录复用共享 TaskStatusIcon SVG：空心圆角方框表示待处理，框内进度弧表示进行中，框内对钩表示完成；新增标签保留在提示与变更摘要中，移除项保留减号和删除线。历史图标静态展示。conversation.input.context 在原生输入框前集中承载队列和目标，order 分别为 0 和 100；容器统一维护首页 heroWorkspaceRow 的背景、顶部圆角及 10px 叠入，抵消 active composer 的 6px 间距。display: contents 槽位包装仍参与 DOM 相邻关系，不能跨包装使用相邻选择器。队列正文独立限高滚动，目标固定在共享容器底部；展开、收起和箭头均有过渡，收起立即退出焦点导航，快速反转及减少动态效果复用 AnimatedCollapse。

- 后台进度是瞬时数据 → 历史聊天只显示已保存的启动和报告事实，不能从启动句柄推断最终完成。
- 去重排除数量没有持久完整计数 → 只说明流程检查，不编造去重数量或百分比。
- 真实 AFP/模型请求涉及账户和成本 → 默认用隔离的模拟像素提供方、会话快照与真实浏览器验证；如未执行线上校验，交付时明确范围。

## Migration Plan

新增摘要字段兼容旧报告与既有工具消费者。Host 与动态 Client 需要重新构建后重启。回滚本次限定文件即可恢复旧展示，不删除运行报告、会话或配置。上游合入时保留 AFP toolview 和思考/压缩记录退出动画检查。

## 故障排查补充

用户运行记录显示：初次任务长时间无输出、报告为 created，未结束时续跑的第二任务失败，随后多次取消重启。原始工作流在连接及收藏夹读取完成后才设置 running；仅凭旧报告无法区分真实卡死与准备阶段。连接单次请求默认 180 秒且可重试两次，会放大无反馈等待。新增持久阶段、准备阶段输出及图片预览/判断计数；各准备阶段使用既有 requestTimeoutMs 限制等待，超时后保存明确失败阶段。同一 Host 的重复 runId 启动在准入前拒绝，跨进程仍使用既有文件锁，不能改写其他任务的运行状态。
