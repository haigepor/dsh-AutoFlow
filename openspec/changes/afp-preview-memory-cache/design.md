## Context

`ImagePreview` 单独 fetch、创建和释放对象 URL，重复预览会重复读取。三个工作台入口已共用插件 store，并具备凭据更新、连接 reset、读取功能变化和 dispose 通知。实现范围限于 AFP 插件，不引入项目级缓存服务。

## Goals / Non-Goals

目标是减少同一预览在图库、详情、清单与下载弹窗中的网络读取，正确隔离请求取消和账号生命周期，并限制保留的 Blob 数量与字节数。浏览器刷新后的持久缓存、Host 磁盘缓存、付费原图缓存、列表虚拟化不在本次范围。

## Decisions

- 插件 store 拥有 `afp-preview-cache.js`，缓存键为当前 store/代次下已验证的同源预览 URL；当前路由固定为 Mockup，未来不同画质需不同键。相比项目公共服务，该模块可直接遵循 AFP 的凭据与权限生命周期。
- 只保留成功栅格 Blob，使用 LRU 和固定 TTL；默认部署值为 300 条、64 MiB、10 分钟，可通过现有部署 JSON 修改，条目数设为 0 关闭保留。相比改 HTTP 缓存头，这种方式不改变同源路由的 `no-store` 与认证要求。
- 同一键合并在途请求，每个消费者独立订阅和取消。成功后获取带 `release` 的 URL 租约；同时显示共用 URL，最后一个租约释放时撤销 URL，Blob 在容量/TTL 允许时保留。淘汰不撤销仍使用中的 URL。
- 组件解码失败使对应缓存版本失效；重试绕过该条 Blob，避免反复使用坏数据。失败、取消、清空后的迟到响应均不回填。
- 私有页面 `status` 增加缓存策略与随机 Host scope。Host 配置重载后 scope 改变，客户端清空旧账户数据并重新读取；Agent `status` 不增加此字段。凭据/连接 reset、读取开关变化和 dispose 也清空缓存，并使组件重建预览订阅。
- 只调整客户端 `ImagePreview` 的数据来源，保留懒加载、骨架屏、完整图片比例与 Modal 交互。真实网络次数和离线性能基准用于验证，不宣称已测浏览器绘制提速。

## Risks / Trade-offs

- 正在使用的图片不能因 LRU 淘汰而突然空白 → 淘汰只移出保留表，租约释放后才撤销 URL；保留容量不等于 DOM、活跃图片和解码总内存。
- 权限通知与远端变化可能存在间隔 → 已知凭据/权限/连接变化立即失效，TTL 限制复用窗口；缓存不替代 AFP 远端授权。
- 缓存清空与旧响应竞争 → 每个请求绑定代次，清空后终止并拒绝旧消费者，迟到响应不可写入。
- 刷新后缓存消失 → 文档明确页面内存范围；持久缓存需另行设计授权与存储期限。

## Migration Plan

旧部署缺少新字段时由插件配置解析补齐默认值。构建、验证并更新 web profile，检查私有状态策略与实际 client 资源。回退使用本次编辑前的插件副本，恢复源码后重新构建与安装；不修改其他项目模块。
