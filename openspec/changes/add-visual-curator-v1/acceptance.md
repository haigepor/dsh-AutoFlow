# 第一版验收与证据映射

本文约定实施时需要提交的证据，当前所有场景均未实现、未执行。OpenSpec 校验通过只说明本提案文档结构有效，不代表下表功能通过；[tasks.md](tasks.md) 保持未勾选。

## 验收层次

| 层次 | 通过条件 | 证据及限制 |
| --- | --- | --- |
| 记录与流程 | 六份规范的全部正向、拒绝、并发和故障场景通过 | package 测试、可控 mock/fixture；模型输出 fixture 不能证明真实审美效果 |
| Agent/打包 | keyless Session 重放、受支持 profile 的 built smoke、bundle exports/依赖完整 | 记录实际命令、产物和快照；不直接执行新增应用 bin |
| Web | 四个工作区闭环、键盘/焦点/窄屏及任务操作通过 | 真浏览器截图、DOM 路径、console/request 记录；调用计数与 Host runId 对应 |
| 真实接口 | 配置的一个图片来源和一个视觉接口完成预算内搜索/裁图及失败归类 | 记录 provider/model 声明、配置 revision、调用数、素材可用性；无输入时明确未验证 |
| 风格效果 | 独立且分组确认的数据上报告接受、漏选、误收、裁图及成本；满足用户预先确认的质量目标才声明达标 | 无质量目标或无人工标签时只报告 provisional/原始指标，不给出臆定通过率；不得用全部拒绝换取“零误收” |

## 指标口径

同一评估固定数据、用途、预算、审查方法和样本分组。模型多次处理同一图片不能增加样本数，原图与裁图指标分开。以下风格指标使用已完成人工标签的评估单位；同一单位多次重试只读取最终执行状态。

| 指标 | 分子与分母 |
| --- | --- |
| 合格结果精确率 | TP / (TP + FP)，TP 为人工正例且系统最终合格，FP 为人工负例但系统最终合格 |
| 端到端召回 | TP / 全部人工正例 P；正例中的 needs-review、技术失败和未处理项仍在 P 中，不因执行失败提高召回 |
| 误收率 / 明确误拒率 | FP / 全部人工负例 N；明确判拒的人工正例 FN / P，另列正例 unknown、失败和未处理数 |
| 待复核 / 技术失败 / 未处理 | 各最终状态唯一单位数 / 全部已纳入单位数；按 source/final 阶段分别展示，不能将多个阶段相加为图片总数 |
| 裁剪接受率 | 明确人工接受成图数 / 完成人工成图复核数，列出其中 unknown；只浏览不进入已复核分母 |
| 主体破坏率 | 明确被标主体破坏的成图数 / 已作主体完整性明确判断的成图数，unknown 单列 |
| 调用与耗时 | 全部实际尝试含重试/outcome-unknown 的账本和任务 wall time；并发阶段耗时不能求和冒充总时长 |
| 费用 | 已知价格配置下的估算与供应商可验证账单分开；缺价格/账单显示 unavailable，硬预算仍使用调用/字节/时间 |

分母为零必须显示 unavailable。版本比较同时展示差异、计数及分母，不以很小样本或被反复调参的 holdout 宣称稳定改善。具体质量目标由试用数据和用户接受条件预先确认，未确认不阻塞结构性验证，也不能被写成已完成审美验收。

## 端到端验收脚本

### T1. 导入、校准、发布和同标准搜索

使用至少两种题材、包含同题材正反例的已授权样例；分别确认整体正例与只参考色彩的图片，处理一个规则冲突并发布 provisional v1。选择手机用途启动目标 10 张搜索，在任务执行中编辑草稿并改变默认，再检查原任务的所有 source/final bundle 仍绑定 v1；回退默认只影响后续任务。fixture 人为仅提供 6 张最终合格，验收实际结果为 6、预算/来源停止原因准确且规则未放宽。

### T2. 反馈修订和版本对比

对任务内一张合风格但错题材图片标记本次不需要，对另一张记录色彩接受/构图拒绝并明确纳入风格；确认前者不入风格负例。修改第二张判断并重试相同 operationId，核对只有一个有效头。生成 candidate v2，对 development 集比较后发布，旧 v1 和旧导出保留；没有有效独立标签时指标显示 unavailable，不声明审美提升。

### T3. 横转竖、真实成图与人工调整

准备已定向和带 EXIF 的横图、足像素单主体、不能同时容纳的双主体及不足像素图。系统分别得到可用、不可合理裁剪和尺寸不足；对同图构造原图合格/裁后破坏的模型 fixture，检查实际成图复核能拒绝。人工拖动后取消不产生理想标签，确认另一合法区域并明确纳入样例后，导出能找到准确父图/区域/反馈，原文件摘要始终不变。

### T4. 故障恢复、隔离和导出

在页面检查点提交后及模型请求发送但未提交时分别终止测试 Host；重新启动后显式恢复，检查已提交不重复、未知尝试保留预算和费用提示。通过其他 Session 请求任务、图片和导出，全部拒绝；停用后无新工具和晚到成功。对同 family 跨 split、带图授权不足、缺损 blob 和旧反馈头构造拒绝输入；导出合法 learning 数据及 Skill，校验清单、checksum、旧包不变及 Home 指令无写入。

## 执行记录要求

每项记录源码版本、fixture 或真实 provider/model、runId、使用的 release/candidate/usage/split、命令或浏览器步骤、预期/实际及产物位置。结果写 PASS、FAIL 或因部署输入缺失而 BLOCKED；只有 fixture 通过的项目不能标记真实接口或审美试用 PASS。所有任务证据完成后才勾选对应实施项；本轮只提交设计产物。
