## Context

当前 plugin-manager 有 pnpm 安装、取消、日志、锁和 manifest/lockfile 恢复；缺少更新源和远程版本检查。bundle patch 使用 installation-first，profile 中的直接依赖则参与 Node 本地解析，必须在更新自定义内置包时统一选择。桌面生产上传已有 desktop-v 标签和独立更新提供方，不需要与 AFP 合并版本。

## Goals / Non-Goals

**Goals:** 从 GitHub 稳定发行检查及安装插件更新；默认自动检查，用户开启开关后自动安装；持久化选择、保留功能配置和禁用状态；更新后重启加载一致；整理可恢复的历史清单并建立独立发行规范。

**Non-Goals:** 不替换基础 DSH 包，不进行热升级，不使用仓库全局 latest 查询 AFP，不发布新的桌面安装包，不改变现有桌面签名或上传提供方，不擅自删除历史记录。

## Decisions

1. 更新源声明在 bundle manifest，使用 GitHub repository、tagPrefix、metadataAsset。安装提供的声明决定同名 profile 副本可否覆盖自定义内置 bundle；保留 @deepseek-ai 官方包的 installation-first。无声明的包保持原规则，避免全局 profile-first 引入基础运行时混用。
2. GitHub Releases 按来源前缀筛选，排除 draft/prerelease，比较稳定 SemVer；afp-update.json 必须匹配包、仓库、标签、版本和公开资产。限定 GitHub 官方 HTTPS 下载地址及重定向、请求时间、分页和字节数，验证大小及 SHA-256；安装前使用 tar 库检查路径、链接、膨胀大小和 package.json 身份。不用 pnpm 直接下载未经校验的远程 URL。
3. 经验证的 tgz 保留在 profile 的私有缓存中，file 依赖重装仍可使用。更新复用现有 pnpm 安装、锁、兼容性检查和诊断；失败恢复 manifest/lockfile 与目标包入口，避免恢复元数据后继续选中新包。更新事务强制 restart-required，不尝试替换运行中缓存的模块。
4. 自动选择存于版本化 profile 配置，默认关闭自动安装。Host 启动与可配置周期执行检查；页面可检查或手动更新。更新进行中合并同包请求，退出时停止下载、安装并等待完成；远程查询失败保留列表和原包，显示可重试状态。
5. 已有 featureConfig 更新保留仍声明的布尔选择，为新增 id 使用新版默认值；拒绝损坏的配置，保留事务恢复所需的旧字节。凭据、用户 patch 和报告不作为更新写入目标。
6. afp-v 与 desktop-v 分别记录产物版本和精确构建提交；其它插件有自己的前缀。正式 Release 必须具有对应安装资产和校验记录；预览用 Actions artifact。经用户明确授权，将原十个标签对象和关联记录备份后，仅重建四个 milestone/ 源码里程碑及正式 AFP 标签。里程碑附注记录来源、用途、功能、验证范围及恢复方法；正式 AFP 来源和资产保持冻结。以后已公开产物标签不移动，预览及测试使用独立前缀。GitHub 没有单独的 tag 归档标志。

## Risks / Trade-offs

- 公共 GitHub API 限流与断网：可配置检查周期，保留状态并允许重试；不把失败说成已是最新版。
- 安装新代码需要重新启动：明确 pending restart，避免热更新带来的 Host/Client 版本混用。
- 来源账户发布恶意更新：哈希保证字节一致而非作者可信；自动安装依赖用户明确开启，来源只能由包声明确定。
- 历史链接受删除影响：本次按已确认清单备份并重建重要标签，最终 Release 仅保留正式 AFP；后续删除与重命名须有对应授权，测试清理不能删除正式资产。

## Migration Plan

发布当前应用源码后才有插件更新能力；旧 AFP 0.1.0 标签和资产保持不可变。新的发行版本按现有独立流程发布。profile 初次读取自动设置默认 false；未声明更新源的包不迁移。更新失败恢复所写文件及包入口；成功更新需要重启。应用代码回退不移动已公开标签。

## Confirmed scope

用户确认建立本变更记录，默认自动检查、显式开启后自动下载安装；正式 AFP 资产保持冻结。用户随后授权备份后删除原十个 Tags，仅重建四个源码里程碑与正式 AFP 标签，并为里程碑补全中文注释；最终 Release 仅保留正式 AFP。测试使用隔离前缀，完成后删除全部临时远程发行及测试产物。

## Update interaction and restart

列表版本标签可直接开始后台更新；详情采用折叠面板，普通策略说明使用中性文本。安装过程向 Client 发布 installing 状态，完成通知由 shell.overlay 全局承载，离开插件页面不丢失。稍后重启保留标签，可再次打开确认。

Web 的 dsh 入口托管 Node 子进程，重启走私有 IPC、有界退出和同命令替换，等待旧进程退出后才复用端口；崩溃及用户中断不重启。启动早期收到停机请求必须保存到 boot 完成后处理。重启接口受现有 Connection 认证与来源检查保护，拒绝旧进程确认和正在进行的包操作。客户端只有观察到不同且就绪的 Host 才刷新页面，保留同来源与已有认证。自定义未托管启动提供准确的手动恢复提示。

桌面端由仅限应用主 frame 的 preload IPC 请求主进程，合并并发请求，复用现有原生退出确认；批准后才安排 app.relaunch 并执行现有 Host 清理，取消不能遗留重新启动计划。两端保留磁盘上的会话和配置，但不承诺运行中的任务跨进程继续；自动下载完成后始终等待用户确认重启。

验证包括启动早期停机 RED/GREEN、真实 IPC/TCP 替换顺序与端口保留、原生确认取消与并发合并、Web 新进程就绪轮询、全局弹窗生命周期及真实 GitHub 临时版本的手动/自动更新与清理。
